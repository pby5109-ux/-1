BLE 指针队列与内存所有权

本课只解决一个问题：队列写入失败后，谁释放 pvPortMalloc 得到的内存？答案是仍然持有指针的 SensorTask。

先把三个对象分开

局部变量 msg
SensorTask 栈上的一个指针变量，里面只是地址。
100 字节消息块
pvPortMalloc(100) 从 FreeRTOS heap_4 取得的动态内存。
BLEQueue 槽位
元素大小为 sizeof(char*)，只复制指针值，不复制 100 字节消息正文。

局部指针变量离开函数会消失，但它指向的堆内存不会自动释放。只有显式调用 vPortFree，那块内存才回到 FreeRTOS 堆。

两个容易说错的地方

  • 不是“堆内数据立刻消失”，而是堆块仍占用、数据可能仍在，但程序失去了可达指针，无法正常访问或释放。
  • 不是“旧指针下一轮自己改变”。当前函数返回后局部变量生命周期结束；下一次调用会创建新的局部变量，malloc可能返回另一块地址。

两条所有权路径

结果队列中是否有指针副本所有权谁释放
入队成功有SensorTask → BLETaskBLETask 在 UART DMA 发送完成后释放
入队失败没有仍在 SensorTaskSensorTask 立即释放
成功路径
malloc → 填消息 → Put=osOK → BLETask Get → DMA发送完成 → free
当前失败路径
malloc → 填消息 → Put失败 → 函数返回 → 指针变量消失 → 堆块无人能找到＝泄漏
正确失败路径
malloc → 填消息 → Put失败 → SensorTask free → 函数返回

最小正确结构

char *msg = pvPortMalloc(100);
if (msg == NULL) {
    return;
}

/* 填充 msg */

if (osMessageQueuePut(BLEQueueHandle, &msg, 0, 0) != osOK) {
    vPortFree(msg);       /* 入队失败，所有权没有转移 */
}
/* 入队成功后，发送者不再访问或释放 msg */

与工程源码对应

  • freertos.c：队列长度 16，元素大小 sizeof(char*)。
  • SensorTask.c：已检查 malloc 失败，但当前没有检查两处 osMessageQueuePut(..., 0) 返回值。
  • cmsis_os2.c：零等待且队列满时返回 osErrorResource。
  • BleTask.c：成功取到指针后，等待 UART DMA 完成再 vPortFree(msg)。
