LCD白屏/花屏：先认清引脚，再沿发送链取证

背光亮只证明背光LED支路工作，不证明LCD控制器已复位、收到初始化命令或写入像素。

当前工程的真实引脚

引脚功能如何观察
PB6 / LCD_BL背光开关万用表可看静态高低；亮屏只证明背光
PB4 / RSTLCD控制器硬复位示波器看低1ms、拉高后等待约125ms
PD2 / NSS(CS)片选，低电平选中LCD逻辑分析仪看传输期间是否拉低
PC12 / RS(DC)低=命令，高=像素/参数数据与SCK/MOSI联合观察，不是背光
PB3 / SCKSPI时钟示波器看电气质量，逻辑分析仪看时序
PB5 / MOSI主机发给LCD的数据逻辑分析仪按SPI模式0解码

当前为SPI屏幕，没有I²C设备地址；由NSS/CS选择器件。

白屏且无SCK的排查顺序

  1. 万用表确认LCD供电和PB6背光；示波器确认PB4复位时序。
  2. 调试器确认LCD任务已创建并进入LCD_BSP_Init()，再进入LCD_Init()和SendCommand()。
  3. 检查HAL_SPI_Init()/HAL_SPI_Transmit()返回值、SPI1状态和错误码。
  4. 确认SPI1时钟、PB3/PB5复用推挽和SPI1重映射已配置。
  5. 逻辑分析仪同时接地并观察PD2、PC12、PB3、PB5。若代码已调用Transmit但PB3仍无SCK，再查外设/引脚/线路。

任务栈不足可能导致HardFault或任务异常，但在“初始化函数是否进入、HAL调用是否返回”之前，不应把它列为第一嫌疑。

花屏时四个关键配置

  • CPOL：时钟空闲电平；当前LOW。
  • CPHA：在哪个边沿采样；当前1EDGE，与CPOL LOW组成模式0。错一位常导致整串位移/乱码。
  • 频率：当前SPI1约18MHz；过高或线路质量差会造成边沿、串扰和间歇错误。
  • RS/DC：命令时低、数据时高；错误会让初始化命令被当像素或像素被当命令。

当前初始化后还补发0x20关闭反色；该命令缺失更偏颜色/反色问题，不等同于完全无SCK。

SPI DMA完成到任务继续的真实链

DMA1 Channel3完成 → DMA IRQHandler → HAL_DMA_IRQHandler → HAL内部SPI DMA完成函数 → HAL_SPI_TxCpltCallback → xSemaphoreGiveFromISR → LCD任务从xSemaphoreTake恢复 → NSS拉高。

DMA硬件不会认识FreeRTOS信号量。它只置硬件完成标志并请求中断；应用层回调才释放二值信号量。若NSS一直低且任务永久等待，按上述链逐个打断点/看状态，找到第一个没有发生的节点。

当前源码的已确认薄弱点：SendData()没有检查HAL_SPI_Transmit_DMA()返回值。如果返回HAL_BUSY或HAL_ERROR，DMA没有成功启动，后面的永久等待就不会收到完成信号量，NSS也会一直保持低电平。诊断时应首先保存并检查该返回值。
