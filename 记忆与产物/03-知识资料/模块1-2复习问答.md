## 模块 1：项目全貌与三档介绍

**Q1. 综合仪器 30 秒介绍怎么讲（带技术钩子）？**

基于 STM32F103RCT6 + FreeRTOS 的口袋综合仪器，集成示波器、信号发生器、可调稳压电源、万用表四台仪器；代码分三层（BSP/GUI/Task）。技术钩子至少一个：ADC 双序列采样、三路 DMA 搬运、事件组 9 位按需重绘。口头报芯片型号要一字不差，可顺带报 256KB Flash / 48KB SRAM / 72MHz。

**Q2. 两个项目的芯片参数？**

仪器：STM32F103RCT6，256KB Flash / 48KB SRAM / 72MHz；农场：STM32F103C8T6，64KB Flash / 20KB SRAM / 72MHz。注意：不存在 STM32F104 这个型号（昨天写错过一次）。

**Q3. 四台仪器哪台负责"输出信号"？**

信号发生器输出波形（DAC → 运放 → ±2V）；稳压电源输出可调直流电压；示波器只采集不输出；万用表只测量。

**Q4. 触发比较器在 MCU 内部吗？触发电平怎么调？**

比较器是板载**外部电路** LM2903DR，不在 MCU 内部。正端接被测信号，负端接电位器（MST22D18G2125，10kΩ）分压出的触发电平，输出接 PA3（EXTI3）。触发路径还有 fc≈8Hz 的低通滤波。

**Q5. 信号调理电路在 ADC 之前还是之后？整个前端链是什么？**

在 ADC **之前**：耦合方式选择 → 衰减倍率选择（2MΩ 网络）→ 同相跟随器 → 增益挡位选择 → 偏置分压 **(V+2.5)/2 → 0.25~2.25V**（即 V/2+1.25）→ 100kHz 低通 → PA1(ADC1_CH1)。保护件 BAV99 + PESD，极限 ±24V，工作范围 ±2.4V。

**Q6. 采样率由谁决定？默认多少？**

由用户选的 X 时基挡位查表决定（12 档），把 ARR 写入 TIM3；TIM3 通过 TRGO 触发 ADC 转换。默认 ARR=561 → 72MHz/562 ≈ **128kHz**，最高 **500kHz**。采样率不是"自适应波形"的，是由时基挡位决定的。

**Q7. 为什么屏幕上波形是稳定的、不左右乱跑？**

触发式采集：每次触发都发生在"上升沿越过触发电平的同一相位点"，每一帧都从信号的同一位置开始采 → 各帧对齐 → 画面稳定不重影。

**Q8. 采样是连续的吗？帧内、帧间什么关系？**

帧内连续均匀（TIM3 每 7.8μs 触发一次转换，1024 点 ≈ 8ms）；帧间有间隔（等下一次触发，中间还有 Hold-Off 10ms）。这是触发式采集，不是连续流。

**Q9. ADC 双序列是什么？万用表和示波器共用 ADC 会打架吗？**

- 常规序列 = 示波器：CH1(PA1)，TIM3 触发，DMA 采 1024 点。
- 注入序列 = 万用表：4 通道（DMM 信号 CH9/PB1、VREFINT、电源电压 CH8/PB0、触发电平 CH0/PA0），TIM2 每 100ms 触发，**优先级高于常规**。
- 抢占顺序：当前这一次常规转换先完成 → 注入 4 通道转换（约 80μs）→ 自动恢复常规序列。
- 不会打架：帧数据不会坏，最坏是该帧时间轴有约 80μs（约 1%）的畸变，屏幕上不可见。

**Q10. 注入序列"抢占"和 FreeRTOS 任务抢占是一回事吗？**

不是。注入抢占是 **ADC 硬件层面的转换顺序插队**，全程硬件自动完成；FreeRTOS 抢占是 CPU 执行流的切换。两套完全不同的机制。

**Q11. 事件组按需重绘怎么工作？9 个位谁置位？**

LCD 任务 `xEventGroupWaitBits` 阻塞等待；谁的数据变了谁置对应位（ADC 完成 ISR → 波形面板位；注入完成 ISR → DMM/电源标签；按键回调 → 面板；Adjust 联动一次可置 3 位）；LCD 任务醒来逐位判断，只重绘"脏"的区域。省 CPU、防闪烁。

**Q12. 不用 FreeRTOS，裸机 while(1) 哪个功能先出问题？**

先纠正：EXTI 中断 + DMA 在裸机里照常工作，"触发 → 启动采样"不受影响（中断会抢占主循环）。真正崩的是并发管理：① 按键 10ms 扫描节拍被可变时长的 LCD 绘制打乱；② 绘制旧帧时新帧数据进中断——关中断画则丢触发、不关则画面撕裂，两害必居其一；③ 6 键 × 4 面板状态逻辑全耦合在一个循环。FreeRTOS 让"采、画、按"按各自阻塞点独立调度。

**Q13. 农场 30 秒介绍要点？**

STM32F103C8T6 + FreeRTOS 环境监测与控制闭环：AHT20/光照/土壤/降雨/NTC 采集 → OLED 显示；按键 + EC11 编码器人机交互；阈值判断 → 水泵（PA12 外接 MOS）、风扇（TIM2 PWM）自动控制；异常 → 蜂鸣器（TIM4 PWM）本地响铃 + JSON 经队列/USART3 DMA 发蓝牙；I2C1 用互斥锁保护。

**Q14. 农场蜂鸣器当前状态？（已核对代码）**

当前脏工作区中`Beep_on()`里的`osTimerStart(BeepTimerHandle, 500)`被注释，因此不能说当前版本已经启用蜂鸣器本地告警。TIM4 PWM和500ms软件定时器设计仍可作为原设计解释，但恢复启动语句后还需要重新编译、烧录和上板验证。

**Q15. 农场 BLE 队列满了会怎样？**

旧代码以0等待调用`osMessageQueuePut`且不检查返回值，队列满时会丢失唯一指针，造成heap_4内存泄漏。当前代码已通过`QueueBleMessageOrFree()`检查Put结果：成功后所有权转给队列/BLETask，失败时所有权仍在SensorTask并立即`vPortFree`；用户确认该修复已完成编译、烧录和上板验证。仍需区分另一条未修问题：`HAL_UART_Transmit_DMA`启动失败可能造成消息丢失，但当前路径最终释放，不是同一个内存泄漏。

**Q16. 个人贡献怎么表述（红线）？**

课程/工具提供：CubeMX 初始化、lcd.a 图形库、教材整体设计；自己实现：仪器 BSP/GUI/Task 层与 One-Shot 功能、农场 NTC/风扇/ADC-DMA 扩展。示例："在课程提供的硬件平台和 LCD 图形库基础上，我自己完成了 BSP 驱动、GUI 面板、任务架构的实现，并独立实现了 One-Shot 单次捕捉功能。"

**Q17. 触发三机制是什么？各一句话 + 时间线。**

1. **触发**（比较器+EXTI）：保证每帧从信号同一相位开始 → 画面稳定对齐。
2. **Hold-Off**（10ms 单次定时器）：触发后屏蔽 EXTI，防采集中途重复触发打断 DMA。
3. **强制触发**（100ms 周期定时器）：超时软件置位触发事件硬采一帧 → 防黑屏。

时间线：t=0 触发 → Start_DMA + 屏蔽 EXTI + 启动 Hold-Off + 复位强制触发 → t≈8ms 采满 1024 点 → t=10ms Hold-Off 到期、清标志、重新使能 EXTI → 100ms 无触发则强制触发兜底。

## 模块 2.1：示波器信号链全景

**Q18. ADC 数据搬运有没有用 DMA？证据在哪？**

有。`APP/BSP/Src/waveform_capture.c:47`：`HAL_ADC_Start_DMA(&hadc1, (uint32_t *)rawDataBuffer, 1024)`；`Core/Src/adc.c:149-156`：DMA1_Channel1、方向外设→内存、NORMAL 模式（采满 1024 个半字自动停）、半字对齐。

**Q19. 为什么这里必须用 DMA？**

最高 500kHz 采样 = 每 2μs 出一个转换结果；逐点进中断 = 每秒 50 万次中断，CPU 会被吃光。DMA 在后台零参与搬完一整帧。

**Q20. 是"边搬边算"还是"搬完再算"？**

搬完再算。DMA NORMAL 模式：1024 点全部进 `rawDataBuffer` 后产生传输完成事件 → 触发 `HAL_ADC_ConvCpltCallback`，在回调里一次性换算 1024 点。边搬边算需要半传输中断或循环 DMA + 双缓冲，本项目没有。

**Q21. 换算公式是什么？和原理图怎么对账？**

`waveform[i] = (rawDataBuffer[i]/4095*3.3)*2 - 2.5`。原理图偏置公式 `([-2,+2]+2.5)/2 = 0.25~2.25V`（即 V/2+1.25），逆运算就是 ×2−2.5——硬件电路与软件公式互相印证。

**Q22. EXTI 中断回调链的完整调用路径？**

`EXTI3_IRQHandler`（stm32f1xx_it.c）→ `HAL_GPIO_EXTI_IRQHandler`（HAL 分发）→ `HAL_GPIO_EXTI_Callback`（业务代码：判断 `GPIO_Pin == Trigger_Pin`(PA3) → `HAL_ADC_Start_DMA` → `HAL_NVIC_DisableIRQ(EXTI3)` → `xTimerStartFromISR(Hold-Off)` + `xTimerResetFromISR(强制触发)`）。

**Q23. Hold-Off 定时器什么时候启动、什么时候到期？到期干什么？**

t=0（触发回调里）`xTimerStartFromISR` 启动，10ms **单次**；t=10ms 到期，回调里先清 EXTI 标志 + 挂起位（防幽灵触发），再重新使能 EXTI3。

**Q24. 强制触发怎么实现的？Auto 模式下每次真触发后对它做什么？**

100ms **周期**软件定时器，到期回调调 `__HAL_GPIO_EXTI_GENERATE_SWIT(GPIO_PIN_3)` —— 软件置位 EXTI 软件事件寄存器，走与真触发完全相同的后续路径。Auto 下每次真触发后 `xTimerResetFromISR` **复位重新倒计时**（不是停止，也不需要恢复）；只有切到 One-Shot 才 `xTimerStop` 停掉。

**Q25. 采样完成后如何通知 LCD？LCD 任务干什么？**

`HAL_ADC_ConvCpltCallback` 换算完 1024 点后：`xEventGroupSetBitsFromISR(波形面板位)` + `portYIELD_FROM_ISR`；LCD 任务 `xEventGroupWaitBits` 醒来 → 按位判断 → `RepaintWaveformPanel()` → `LCD_DrawWaveform()`（清波形区 → 网格 → 折线 → 触发虚线 → 游标线）→ `SendData` 发起 SPI DMA → 二值信号量等完成（项目的第三路 DMA）。

**Q26. One-Shot 模式的状态机？**

进入 One-Shot：停强制触发定时器 → 清 EXTI 标志 + 挂起位 → 使能 EXTI → `ucOneShotArmed=1` 待命。触发一次：Start_DMA + 屏蔽 EXTI，**不启动 Hold-Off**，EXTI 保持禁用 → 波形冻结。切回 Auto：清标志、使能 EXTI、重启强制触发；再切 One-Shot 重新武装。清标志的意义：防"幽灵触发"（残留挂起位导致一使能就误触发）。

**Q27. 板载还有哪些没接入业务的资源？**

M24C64 EEPROM（I2C，PC10/PC11）、2.4kHz 有源蜂鸣器（PA15，Q2 驱动）。面试可说"板载资源预留，未接入业务"。

## 易错点清单（昨天踩过的坑）

1. **128Hz** → 应为 **128kHz**（差 1000 倍）。
2. "t=10ms 定时器启动" → Hold-Off 是 **t=0 启动、t=10ms 到期**。
3. "关闭/恢复强制触发定时器" → Auto 下是**复位重新计时**，不停也不恢复；只有 One-Shot 才停。
4. "输出信号的是示波器" → 输出信号的是**信号发生器**。
5. 函数名拼写：`HAL_ADC_ConvCpltCallback`、`xEventGroupSetBitsFromISR`、`xEventGroupWaitBits`、`RepaintWaveformPanel`、`EXTI3_IRQHandler`。
6. "波形监测间隔约 10ms" → 10ms 是 Hold-Off 屏蔽期；帧长 = 1024 点 ÷ 采样率（128kHz 时 ≈ 8ms）。
7. "注入只要几微秒" → 约 **80μs**（4 通道 × 239.5 周期 @ 12MHz）。
8. 比较器是**板载外部电路**（LM2903DR），不是"MCU 内部的触发器"。
9. 采样率不是自适应，是**时基挡位查表**决定 TIM3 的 ARR。
