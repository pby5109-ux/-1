void vTaskFunction( void *pvParameters )
{ 
    char *pcTaskName; 
    portTickType xLastWakeTime; 
    pcTaskName = ( char * ) pvParameters; 
 
    /* 变量 xLastWakeTime 需要被初始化为当前⼼跳计数值。说明⼀下，这是该变量唯⼀⼀次被显式
赋值。之后， 
    xLastWakeTime 将在函数 vTaskDelayUntil() 中⾃动更新。  */ 
    xLastWakeTime = xTaskGetTickCount(); 
 
    for( ;; ) 
    { 
        vPrintString( pcTaskName ); 
        /* 本任务将精确的以 250 毫秒为周期执⾏。同 vTaskDelay() 函数⼀样，时间值是以⼼跳周
期为单位的， 
        可以使⽤常量 portTICK_RATE_MS 将毫秒转换为⼼跳周期。变量 xLastWakeTime 会在 
        vTaskDelayUntil() 中⾃动更新，因此不需要应⽤程序进⾏显⽰更新。  */ 
        vTaskDelayUntil( &xLastWakeTime, ( 250 / portTICK_RATE_MS ) ); 
    } 
}

优先级反转
有优先级为 A 、 B 和 C 三个任务，优先级 A>B>C ，任务 A ， B 处于挂起状态，等待某⼀事件发⽣，任务 C 正在运⾏，
此时任务 C 开始使⽤某⼀共享资源 S 。在使⽤中，任务 A 等待事件到来，任务 A 转为就绪态，因为它比任务 C 优先
级⾼，所以立即执⾏。当任务 A 要使⽤共享资源 S 时，由于其正在被任务 C 使⽤，因此任务 A 被挂起，任务 C 开始
运⾏。如果此时任务 B 等待事件到来，则任务 B 转为就绪态。由于任务 B 优先级比任务 C ⾼，因此任务 B 开始运
⾏，直到其运⾏完毕，任务 C 才开始运⾏。直到任务 C 释放共享资源 S 后，任务 A 才得以执⾏。在这种情况下，优
先级发⽣了翻转，任务 B 先于任务 A 运⾏。
优先级继承
freertos 使⽤优先级继承来解决优先级反转问题  当任务 A 申请共享资源 S 时，  如果 S 正在被任务 C 使⽤，
通过比较任务 C 与⾃⾝的优先级，如发现任务 C 的优先级⼩于⾃⾝的优先级，  则将任务 C 的优先级提升
到⾃⾝的优先级，  任务 C 释放资源 S 后，再恢复任务 C 的原优先级。
