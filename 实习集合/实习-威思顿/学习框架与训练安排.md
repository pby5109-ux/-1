# 威思顿实习学习框架与训练安排

目标是先弄清电表结构、功能和测试方法，能解释原理、分析给定场景，再依据实际经历完善简历。最新进度见[统一接续记忆](../../记忆与产物/00-项目接续记忆.md#track-oral)。

## 三条学习主线与八个板块

| 主线 | 板块 | 必须能说明 | 代表追问 |
|---|---|---|---|
| 结构 | 1 产品与系统位置 | 电表、采集终端和主站的分工，量值及业务数据流 | 电表与终端有什么不同？ |
| 结构 | 2 三相与计量基础 | 三相四线、相/线电压、有效值、正反向、有功与电能 | 为什么380V？kW与kWh有什么区别？ |
| 结构 | 3 功能单元 | 电源、输入调理、采样/计量、MCU、存储、时钟、通信与防护的职责 | 电压怎样变成显示读数？ |
| 测试 | 4 测试与测量 | 对象与版本、条件、参考值、单位、误差、预期、实际与证据 | 如何测试电压读数、电量累计？ |
| 功能 | 5 事件与上报 | 异常输入、判据、事件成立/恢复、记录及发送的区别 | 本地有事件却没收到通知怎么办？ |
| 功能 | 6 远程费控 | 请求、认证/权限、允许条件、控制输出与状态反馈 | 允许合闸为何不等于已送电？ |
| 结构/功能 | 7 通信 | UART、RS485、电力线载波与应用协议；调制、耦合、接收 | A/B是什么？载波怎样进入电力线？ |
| 测试 | 8 分层排查 | 供电接线、信号输入、通信参数、软件状态；每层的区分证据 | 终端采集失败怎样缩小范围？ |

非技术补充：团队角色、任务安排、组会汇报、问题单、交接复测、权限与资料管理。IP68案例独立学习，不能默认属于本型号。

## 教学方式

用户明确要求先完整补充自己知道的流程和内容，助手仅接收、分类和记录，不主动转入教学、出题或评分；不要因用户说“不知道”就自动开始讲课。待用户表示补充完成，再共同整理任务、协作、汇报与问题过程，并确认何时进入学习训练。此前脉冲换算题暂停，不要求回答。

经历润色应让实际学习/参与内容具体、连贯、便于追问；可补充通用流程和模拟工作场景帮助理解，但不得把未经发生的操作、故障、同事或结果当作真实履历。正式切换训练后每轮2～3道关联题，逐题回答、纠错与复述；每个模块准备30秒概括、1～2分钟链路解释及条件变化追问。评分只在聊天中反馈。

建议顺序：整机定位→计量基础→模块与数据链→读数/电量测试→通信→事件与费控→排查与交接。用户可按补充内容调整顺序。

验收依据：能说清职责和因果，能算带单位的小例子，能设计正常/异常/恢复检查，能提出两个候选原因及区分证据。读完材料不直接判为通过。

## 完整工作过程演练的构建流程

面向嵌入式工程师及电子信息相关岗位，以用户补充的经历为起点，形成有来源的经历梳理和明确标注的工作场景演练。演练帮助学习任务流转与技术追问，不作为实际在公司的工作记录。未确认的日期、团队人数、设备、工具和成果保持待核实。

### 1. 收集材料并确认边界

用户可以自由描述，每条整理为：在公司亲历并记得的内容、现在学习后能解释的内容、设想或希望练习的任务、尚不确定的细节。分别记录来源与证据，不能把“听过讲解”“看过操作”“亲手操作”“独立完成”混为一谈。

输入提示：公司里听过/看过/做过什么；现在能解释哪些原理；希望设想什么工作；实际使用或只见过哪些工具；实习时长与目标岗位（不确定可暂留空）。先接收用户内容，再逐项追问，不要求一次填写完整。

完整报告的材料类别：入职背景与时间；产品/安全培训的内容；后续2～3项核心任务及参与范围；工作环境、设备与工具；带教、同事协作及任务分配；记录、汇报和交接；问题现象、排查、处理与复测；学习产出及总结。用户可按任意顺序补充，不要求一次回答所有类别。每日安排在材料齐全后统一编排，不先填满日历。已补充的公司、科技质量部、协议及培训活动见《简历内容讨论》，该事实清单不在计划内重复维护。

讨论规则：原先按用户要求每轮一项；2026-10-05用户要求加快，本阶段改为关联板块成组补充，减少逐个细节的来回，关键材料集中询问，非关键未知项暂留待核。先复核已有内容，再整理可审阅草案；用户确认后标为定稿并保留确认范围。各条正文统一维护在《简历内容讨论》，后期整体报告复用已定稿段落，不将待确认草案直接写成事实。事实、回忆不确定与推演补充保持可辨认，不因用户认可模拟表述就认定其历史发生。当前仍是材料与工作过程整理，不主动转入技术教学或训练，不提前填写虚构逐日工作日志。

### 2. 选出2～3项能逐步掌握的任务

候选方向：模块与数据链梳理；显示读数或电量累计的测试方案；RS485通信检查与采集异常排查。事件、费控和主动上报按学习基础再加入。实际测试需明确样机、配置、环境及受指导的操作范围；没有设备时采用手册分析、示例数据和桌面推演，结果明确写为演练。仪表使用、程序编写、协议分析及软件修改，只有得到实际操作证据后才能描述为已掌握或完成。

### 3. 为每项任务建立完整任务卡

用户另提出手册式的测试过程构建。后续可编《智能电表测试学习指导书（教学版）》，包含对象及资料来源、条件、用例、预期、记录、判定、异常与复测；明确由本学习任务编写，不作为公司或原厂手册。尚未发生的测试只作推演，不生成冒充实测的日志或完成结论。未确认开发板型号/接口时不指定接线端子、程序、寄存器或协议参数，不把拆开的电表主板直接称为开发板。先完成逐条材料讨论，再据确认范围编写。

| 内容 | 需要说明 |
|---|---|
| 背景与目标 | 谁提出需求、对象及版本、为什么做、完成标准 |
| 条件与步骤 | 输入条件、配置、参考值、正常/异常/恢复检查、记录格式 |
| 工具与输出 | 使用什么、具体怎么用、输出文档或数据；区分实际操作与拟学习 |
| 协作与汇报 | 自己负责什么、向谁请教、需要谁确认；进展、证据、阻碍、下一步 |
| 问题与处理 | 现象、候选原因、区分证据、处理职责、复测及遗留问题 |
| 面试追问 | 为什么这样做、换一个条件怎么办、能证明什么、哪些仍未知 |

异常场景不能仅凭“采集失败”断定根因；完整过程应表现假设、检查、缩小范围和复测。软件状态可作为检查层级，但不默认用户修改过固件。

### 4. 编排过程与日程

原先按1～2个月构建；用户确认实习约一个月，月份范围2025年10月到2025年11月，具体起止日仍未知。完整正文统一维护在[一个月实习报告与工作过程学习](一个月实习报告与工作过程学习.md)，不拆成独立的事实报告和演练报告。按“入职了解→产品学习→受指导练习→任务记录→问题分析→总结交接”编排；缺少具体日期时，用20个学习工作单元表示每日任务，不映射真实出勤、星期或节假日。实际内容、自学校验和补充场景在同一报告中标明来源。每日说明目标、活动、协作、拟产物及理解重点，允许资料复习和结果检查。团队按角色组织，不宣称真实人数、会议频率或未确认职责。

#### 一个月报告的阶段编排（演练）

以下是报告组织方案，不是回填的实际周次或每日历史；两次检修日期、7天培训与两个1天活动的重叠情况仍未确定。

| 阶段 | 报告组织内容 |
|---|---|
| 第1周 | 入职和部门接待，参观、安全培训，开始多款电表讲解 |
| 第2周 | 完成产品讲解，阅读典型表手册和观察主板，衔接校验学习与指导练习 |
| 第3周 | 校验学习/演练、批次复核；组织RS485支路检修案例的参与过程和复盘 |
| 第4周 | 组织载波模块检修案例，补充资料整理、工具用途和月末学习总结 |

7天产品讲解可跨前两周组织，但不认定为连续7个工作日；两个检修案例暂放后半段仅便于叙事，不证明当时发生周次。每周一次复盘、周记录及月末总结均为用户要求补充的拟定学习安排，形式正文只维护在《简历内容讨论》；历史是否存在仍为回忆不清。

完整报告覆盖岗位背景、阶段/每日过程、具体任务、协作汇报、工具、问题处理/复测、学习产物与总结，并附简历对应和待核清单。阅读后按实际问题增量修改该文，原始讨论、参考和训练文件继续按各自职责维护。它不替代内部指导书，也不新增高难度开发或历史测试成果；真实断点只维护在主接续记忆。

### 5. 学习、追问与表达训练

每次选一个任务：讲清原理和步骤→用户复述→2～3道关联追问→变更条件的排查演练→简短进度汇报。掌握标准是能解释目的、条件、证据和结论，遇到未知能提出下一项检查；不以背熟故事作为掌握证明。训练结果记录在本目录《技术学习与讨论记录》，简历措辞在《简历内容讨论》中逐步核实。
