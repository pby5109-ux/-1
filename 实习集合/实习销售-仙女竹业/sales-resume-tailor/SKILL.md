# 销售简历定制 Skill（sales-resume-tailor）

## 0. 定位与边界

- 目标简历：**掌握部分技术的销售**——B2B 解决方案销售叙事＋技术差异化背书，一页 A4，仅交付 PDF。
- 当前正式交付：`../彭博裕-客户经理.pdf`（2026-09-26 用户批准竞赛行"蓝桥杯省级三等奖；电子设计大赛校级一等奖"后由构建脚本重生成；SHA256 `68b255b51e33ef3f362e54eaa25fc1a9c0192f2ec3c5c66413c6bfcf319fcf29`；1 页，9pt/行距236，短尾行已清理）。
- **与技术简历完全隔离**：技术简历及其定制 skill 在 `../../../简历/jd-resume-tailor/`，两边素材池、流程、断点互不影响；本 skill 不得向技术简历回写任何内容。
- 本 skill 的所有文件、脚本、记录统一存放在 `实习集合/实习销售-仙女竹业/`（用户指定唯一存放地，2026-09-26 迁入`实习集合/`）。

## 1. 接续必读（按序）

1. `references/sales-writing-spec.md` —— **唯一规范**：定位、两类 JD 对位表、版式参数、生成管线、六大板块写法与细节、硬规则与检查清单、按 JD 切换规则、已知不足与改进项（§6）。
2. `../内容讨论与候选.md` —— 内容定稿过程、用户逐句审核结论、当前状态（历史依据，正文冲突时以构建脚本为准）。
3. `../版式架构基准.md` —— 版式实测原始数据与已知瑕疵（3CU 笔误等，重建时不得照抄）。

## 2. 事实与素材边界

- **正文唯一机器源**：`../中间文件/build_sales_resume.py` 的内容字典（P1/P2/INTERNSHIP/CAMPUS/SKILLS）。**改正文＝改脚本后重建，禁止手改 PDF**。
- 数字只用用户原话口径（客户 100 余名、多个万元级与数十万元级订单、优秀销售实习生）；不汇总总额、不写客户名与订单明细、不出现"竹"字品类、团队指标必须标注归属。
- 无证据不写：CRM 经验、网络协议栈知识、"沟通能力强"类自评、任何销售类证书。
- 禁串与必需串清单固化在 `../中间文件/export_and_check.py`，每次生成自动校验。

## 3. 工作流（两阶段闸门，先预览后生成）

### 阶段一：JD → 匹配预览

1. 解析用户 JD：区分硬性要求/优先项/软素质，对照 spec §1 对位表逐项匹配，**缺口如实说明，不为 JD 硬凑证据**（技术版规则沿用）。
2. 判断改动量：
   - **小改（≤3 处文字微调）**：给"位置→原文→替换文"清单，用户手改或授权代改；代改＝改 build 脚本内容字典后走阶段二。
   - **大改（板块增删/重排/新变体/换意向标题）**：先出**文字预览**（全板块文案），用户批准后才允许生成。
3. 意向标题按 spec §5 切换（客户经理 ↔ 销售工程师（数通/物联网方向）↔ 销售代表），不维护多份简历。

### 阶段二：生成与验收

4. 构建：`python ../中间文件/build_sales_resume.py <输出.docx> <字号9|8.5|8> <行距> <段前>`（字号回退链见 spec §2.3：9pt/236 → 9pt/212 → 8.5pt/212）。
5. 导出＋四项检查：`python ../中间文件/export_and_check.py <docx> <pdf>`——页数=1、必需串 20 项全命中、禁串 14 项零出现、底部留白正常。
6. 孤行检查：`python ../中间文件/scan_tails_v3.py`——出现"一行只有几个字"的短尾行**必须回脚本改写文字消除，不许带病交付**；合法窄行（板块标题、表格日期/专业栏、右对齐关键词）豁免。
7. 渲染自查：`python ../中间文件/render_and_scan.py` 出 150dpi 整页 PNG；视觉验收代理可用时派独立验收，不可用时主代理自查并**如实记录"非独立验收"**。
8. 交付：仅 PDF，临时 docx 删除；输出路径被占用时不覆盖、改新名并告知用户关闭占用程序；正式文件名 `彭博裕-<岗位名>.pdf`。
9. 收尾：按工作区协议领 resume 锁更新 `../内容讨论与候选.md`，领 memory 锁更新 `../../../记忆与产物/00-项目接续记忆.md` 的 track-resume-sales 段。

## 4. 已知不足与下一步（截至 2026-09-26）

详见 spec §6（8 项）。最高优先级：①展会订单面试口径成稿；②实习跨学期一句话口径；③投数通类公司前补网络基础；④建立销售面试训练专题（模拟推销/异议处理）。用户提出改进方向时从 spec §6 接续，不重复考古。
