## 1. 定位与适用岗位

**定位一句话：掌握部分技术的销售（B2B 解决方案销售），不是纯技术岗，也不是纯关系型销售。**

两类参考 JD（画像用途，不逐句定制）：

| | 信锐科技·客户经理类 | 泛理工科·销售岗类 |
|---|---|---|
| 产品域 | 数通/物联网，政企大客户 | 未限定的理工科产品 |
| 专业门槛 | 专业不限 | 泛理工科优先（计算机/信息/通信/机械/自动化/材料） |
| 核心动词 | 客户关系构建、销售项目总指挥、商机到交付全流程资源调度 | 客户开拓维护、需求痛点→方案适配、CRM 信息化工具、组织市场活动 |
| 软素质 | 沟通表达、逻辑思维、人际理解、敢于挑战 | 沟通人际、客户导向、营销意愿、目标导向、抗压应变、诚信、团队、出差 |

**简历策略**：一份通用版覆盖两类。人事先看软素质证据（实习业绩＋校园统筹），技术背景（物联网工程专业＋两个项目＋电力行业接触）作为"专业不限"申请池中的差异化背书保留但不堆砌。

### JD 要求 → 简历证据对位表

| JD 关键词 | 简历中的对位证据 |
|---|---|
| 销售业绩/客户开拓 | 实习·销售业绩条（展会柜台营销、客户100余名、万元级与数十万元级订单、优秀销售实习生） |

| 组织市场活动 | 校园·组织统筹（厂商校级宣讲、校级赛事组织） |

| 团队合作 | 项目二全条（协作叙事） |

| 适应出差 | 技能·资质行（C1＋适应出差与驻外）；实习·多地推广 |
| 正直诚信 | 全文无编造（写作规则第4节） |

## 2. 模板格式与生成管线

### 2.1 版式骨架（实测自技术版 -10.pdf，详见版式架构基准.md）

- 一页 A4；板块顺序（销售版实际顺序）：**页眉 → 教育背景 → 竞赛与荣誉 → 实习经历 → 校园经历 → 项目经历 → 专业技能**（实习、校园前移至项目之前，这是与技术版的唯一顺序差异）。
- 每个板块标题下压深蓝 #1F4E79 全宽细线；项目之间黑色细线分隔；正文 #202733。
- 排版参数（销售版定稿实测）：正文 **9pt**（微软雅黑，西文 Arial）、行距 w:line=236、板块标题段前 1pt、姓名 21.5pt、项目/标题行 9pt 加粗＋右侧加粗关键词（右对齐）、正文色 #202733；底部留白 34.4pt。
- 页眉：姓名＋同行"求职意向：×××"（深蓝加粗）＋联系方式行（电话/邮箱/2027届）＋右上证件照。

### 2.2 生成管线（全部脚本在 `../../中间文件/`）

1. **基准**：`简历/简历修改版本/模板简历（随时跟新）/彭博裕-嵌入式软件工程师-含实习与校园.docx`（SHA256 `E6E12275…06236`；只用其版式骨架，正文全部替换）。
2. **构建**：`build_sales_resume.py <输出.docx> <字号9|8.5|8> <行距> <段前>`——替换求职意向、23 处正文、3 个标题行；校园短段替换为两条加粗标签条目；实习块与校园块前移至项目经历之前；删除 LoRa 项目块；按配置改字号/行距。**只 `word/document.xml` 与基准不同，其余 ZIP 部件逐字节保留**（既定契约）。
3. **导出与检查**：`export_and_check.py <docx> <pdf>`——Word COM 导出 PDF；检查页数、底部留白、20 个必需串、14 个禁串。
4. **孤行扫描**：`scan_tails_v3.py`——逐行检测宽度 <100pt 的行并列出上下文；合法窄行豁免：板块标题、表格单元格（日期/专业栏/右对齐关键词）。
5. **渲染自查**：`render_and_scan.py` 出 150dpi 整页 PNG，人工查验（视觉验收代理不可用时按回退由主代理自查并如实记录）。
6. **交付**：仅 PDF，临时 docx 删除；输出路径被占用时不覆盖、改新名并告知用户关闭占用的阅读器。

### 2.3 字号回退链

9pt/236（当前，因销售版少一个项目而达成，优于技术版含实习上限 8.5pt）→ 溢页则 9pt/212 → 再溢则 8.5pt/212（技术版实测口径）→ 二级回退：办公技能与 AI 工具两行合并为"数字工具"一行。

## 3. 各板块书写内容与细节

### 3.1 页眉

- 求职意向写**具体岗位名**：默认"客户经理"；投技术销售/售前类换"销售工程师（数通/物联网方向）"；投泛理工类销售代表岗换"销售代表"。**母版可替换标题机制，不为岗位名维护多份简历。**
- 联系方式与届别照技术版；证件照保留。

### 3.2 教育背景、竞赛与荣誉

照技术版不动：四栏教育行（时间｜学校｜专业｜学历｜排名前10%）；竞赛三行（比赛获奖/证书荣誉/项目实践）。这是诚信与学习能力的背书层，不为销售化改写。

### 3.3 实习经历（销售简历的主菜）

**结构**：标题行（公司全称｜岗位｜起止年月）＋三条"加粗标签"条目，**结果前置**：

1. **销售业绩**——展会、客户量、订单级别、奖项，一 条说完硬结果；
2. **产品与工艺**——懂产品是技术销售的说服力来源；
3. **市场推广**——多地推介、不同客户群体、一线沟通积累。

**写作规则**：

- 数字只用本人原话口径：客户"100 余名"、订单"多个万元级与数十万元级"——**不汇总总额、不写具体客户名、不写订单明细**（面试被追问时按本人真实记忆口述，简历不预设口径）。
- 奖项照实写"获评公司'优秀销售实习生'"。
- 产品品类（竹制品）**不在正文出现**——投递方向是技术工科类销售，品类由公司名自明；只写"产品线、品质标准、生产工艺"等科技生产元素。
- 公司写注册全称"湘潭市仙女竹业有限公司"。
- 若未来某版无销售实习：本板块不虚构替代，宁缺毋滥（当前未建无实习变体）。

### 3.4 校园经历

两条"加粗标签"条目，标签语义对位 JD：

- **组织统筹**：50 人部门、校级赛事与厂商宣讲、人员分工/跨部门协调/流程落地——对位"销售项目总指挥""组织市场活动"；
- **现场应急**：200 余人活动、主备双方案、故障按预案切换并快速恢复——对位"应变力/抗压"。

真实数字保留；不写"零中断"类未经测量的绝对化表述。

### 3.5 项目经历（两项目，销售化改写）

**改写三原则**：①事实底座与技术版完全一致，只换讲评视角；②不编造客户、商务或业绩情节；③团队指标必须保留团队归属。

- **基于STM32的多功能综合测量平台**｜关键词：多功能集成 · 统筹推进 · 指标交付——讲"个人把一个多模块产品从方案推进到交付"的故事（对位"商机到交付"）；标题写品牌级"STM32"，不写完整型号 F103RCT6。
- **基于MSPM0与K230的移动目标瞄准系统**｜关键词：跨角色协作 · 需求对接 · 团队交付——讲"与控制方向队友拆需求、定协议、联调交付"的故事（对位"客户关系/资源协调"的缩影）；指标 2 秒/＜1.5cm/＜2cm 标注"（团队指标）"。
- 四字标签体系：方案统筹/问题攻坚/交付闭环、需求拆解/接口沟通/团队交付——主题化、可展开为面试故事；不用"项目背景/职责/成果"式空标签。

### 3.6 专业技能（5 行体系）

| 行 | 内容要点 | 取舍逻辑 |
|---|---|---|
| 技术基础 | 物联网工程专业、嵌入式/传感器/通信协议、读图纸手册、设备调试与产品演示 | 首行立"懂技术的销售"人设；技术面试官可验证 |
| 工程素养 | 仪器定位问题、以实测数据支撑结论、CMake/GCC/Git | "逻辑思维+数据习惯"的证据；工具名保留技术可信度 |
| 办公技能 | WPS/Office 文档、数据、演示材料 | 对位"销售信息化工具"；技术版因无关弃用，销售版恢复 |
| AI 工具 | Codex/Claude Code/DeepSeek Harness/ZCode 搭建工作流，辅助资料整理与演示内容制作，快速完成产品设计与开发 | 工具适应力证据；面试需能举出真实工作流例子 |
| 资质 | C1 驾驶证，适应出差与驻外 | 对位 JD"适应出差"；技术版弃用、销售版恢复 |

**不写**：CRM/销售管理软件经验（无证据）、"沟通能力强"类自评（证据在实习与校园，不写空话）、营销类证书（没有）。

## 4. 硬规则与检查清单

1. **一页 A4 是硬约束**；每次重排必须跑 `scan_tails_v3.py` 孤行检查（短尾行="一行只有几个字"，用户明确反感）。
2. **必需串/禁串清单**随 `export_and_check.py` 自动校验；禁串含：LoRa、威思顿、智能电表、嵌入式软件工程师、竹制品/竹材、FreeRTOS、旧技术标签（编程基础/内核与实时系统/科创组织/现场保障等）。
3. **诚信边界**：不编造任何数字与情节；用户原话口径优先；团队指标标注归属；无证据的能力不写（CRM、网络协议栈、客户行业知识等）。
4. **交付**：仅 PDF；临时 docx 删除；文件被占用不覆盖、改新名；正式文件名建议 `彭博裕-<岗位名>.pdf`（当前：彭博裕-客户经理.pdf，用户自定）。
5. 修改正文一律改 `build_sales_resume.py` 中的内容字典后重建，**不手改 PDF**；重排后必需串/禁串/孤行/页数四项检查全过才算候选。

## 5. 按 JD 的切换规则

- **求职意向标题**：按第 3.1 节替换，其余不动。
- **LoRa 变体**（仪器换 LoRa 节点）：仅当定向投数通/物联网公司（如信锐类）且用户要求时再建——LoRa 的 RF/功耗无实测证据，销售面试讲产品故事时更易被追问，通用版不启用。
- **双组合并存**：如未来需要"通用版＋信锐定向版"，仿技术版组合机制，各存一份批准 JSON/脚本配置，不混写。

## 6. 当前已知不足与后续改进项（2026-09-26 自查）

1. **展会订单面试口径未成稿（最高优先级）**：数十万元级订单必被追问——客户类型、金额区间、成交过程、是否交付回款。需要用户口述一轮并整理成面试准备材料。
2. **实习时间跨学期的口径**：2024.06—2024.10 含 9–10 月在读时段，面试可能问"如何兼顾学业"，需要一句话真实解释（如暑期全职＋秋季周末/远程），不能现场编。
3. **数通/网络基础知识为零**：投信锐类数通公司，路由器/交换机/企业网络基础概念大概率被问；物联网工程专业覆盖一部分，但建议投递前集中补一次（面试用，不进简历）。
4. **销售面试形式未训练**：模拟推销、场景题（"把这支笔卖给我"）、客户异议处理等，与嵌入式技术面试完全不同，建议建一个销售面试训练专题。
5. **变体未建**：无实习版、无校园版、LoRa 定向版均未生成；当前只有"实习＋校园＋两项目"一版。
6. **AI 工具行的扩展用途**（资料整理/演示内容制作）是合理延伸表述，面试要能给出真实例子支撑。
7. **视觉验收代理不可用**（provider-not-found）记录在案：本次为回退自查；后续如可用应补独立视觉验收。
8. 若投非快消/非日用品行业，实习条目的"上海日用品展览会"行业属性可能被问"为什么从日用品跳到我们行业"——答案应是"展会销售方法论通用＋对贵行业产品的学习能力"，建议纳入面试准备。
