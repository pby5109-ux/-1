## 2. 版块顺序与槽位骨架（自上而下）

1. **页眉区**（无分隔线）：左上姓名（大号深蓝加粗）＋同行"求职意向：×××"（深蓝加粗）；下一行联系方式：电话、邮箱、届别（标签与值同字号，值为西文字体）；右上角证件照。
2. **教育背景**：单行四栏表格——时间段｜学校｜专业｜学历｜排名（四栏 x 起点 36.7 / 167.2 / 297.7 / 462.9）。
3. **竞赛与荣誉**：若干行"**加粗标签**：内容"式整行文本。
4. **项目经历**：N 个项目，每个项目为——
   - 标题行（双栏）：左＝项目名（加粗 9pt），右＝三个加粗关键词（右对齐，`·` 分隔）；
   - "**项目简介**：…"一到两行；"**项目职责**：…"一行；
   - 若干条"• **四字标签**：内容"条目，续行悬挂缩进（x≈46.9）。
   - 项目之间以黑色细线分隔（不是加粗蓝线）。
5. **校园经历**：组织标题行（加粗 9pt，含蓝色小号"｜职务"后缀）＋若干条"• **加粗标签**：内容"条目。
6. **专业技能**：若干行"**加粗标签**：内容"（每行一个主题，不合并）。

每个板块标题下方压一条全宽深蓝色细横线（板块标题与内容之间）；技术版共有 5 条蓝线（教育背景、竞赛与荣誉、项目经历、校园经历、专业技能）＋ 2 条项目间黑线。

## 4. 结构性约束（沿用技术版既有规则，销售版是否沿用逐条商讨）

- 一页 A4 是硬约束；字号放大受行距压缩限制（8.5pt 为含较多内容时的实测上限）。
- 标题行必须保持"左名＋右关键词"两个单元格结构，不能合并单元格（会破坏对齐）。
- 每个项目名称后跟三个加粗关键词，且关键词必须有真实经历支撑。
- 四字标签主题化（如"科创组织/现场保障"式），不使用空泛的"项目背景/职责/成果"。
- 技术版默认无"自我评价"栏、无页首技能标签行、项目不写日期与角色——销售版是否沿用待商讨。
- 交付仅 PDF，不留 docx 成品；临时 docx 仅用于驱动导出后删除。

## 5. 基准文件已知瑕疵（销售版重建时不得照抄）

- 正文"国产3CU产品"为"国产MCU产品"的键入笔误（渲染层即为 3CU）。
- 简介中"频率档位覆盖 50 Hz～80kHz"与唯一源码冲突（源码末档 50 kHz），内容库已按 50 kHz 收敛。
- 有一处孤字 span 使用宋体（SimSun）渲染（"级。"），属模板字体回退残留，重建时应统一为微软雅黑。

## 6. 内容层待商讨清单（占位）

- 求职意向的具体岗位名（销售代表/销售管培生/销售工程师/技术销售…）。
- 各版块取舍与顺序：销售简历中"校园经历/竞赛荣誉"权重是否上调、项目经历如何压缩改写、是否新增"实习/实践"栏、专业技能改写为销售相关能力。
- 三关键词、四字标签体系的销售化语义。
- 是否保留证件照、联系方式行结构。
