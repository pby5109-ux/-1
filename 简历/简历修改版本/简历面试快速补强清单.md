# 简历面试快速补强清单

> 用途：记录已经确定要写入或准备写入简历、但当前原理或表达不够稳定的内容。每项必须补到能够解释、操作或演示的验收线，避免“简历写了，面试问不出来”。  
> 本文不维护简历当前定稿进度；具体简历文字见`简历内容讨论与定稿记录.md`，当前任务断点见`../../记忆与产物/00-项目接续记忆.md`。

## 1. 使用规则

- `P0`：写入嵌入式简历前必须补齐；面试高概率直接追问。
- `P1`：项目深挖或工具追问时常见，完成P0后补齐。
- `条件保留`：通过验收才写入最终简历，否则删除对应关键词。
- 每一项至少达到：一句话定义、项目中的实际用途、一次操作或故障场景、明确能力边界。

## 2. P0：构建、调试与版本管理

### 2.1 Git基础工作流

**简历候选表述：** `使用Git进行版本管理。`

**当前状态：** 理解Git用于记录提交、编写提交说明和分支管理；常用命令及三区关系需要复习。

**快速补强：**

- `git status`：查看工作区和暂存区状态。
- `git diff`、`git diff --staged`：分别查看未暂存和已暂存差异。
- `git add`、`git commit`：将修改加入暂存区并形成提交。
- `git log`：查看提交历史、作者、时间和提交说明。
- `git branch`、`git switch`：查看、创建和切换分支。
- 说清工作区、暂存区、本地提交和远端仓库的区别；理解`commit`不等于`push`。

**验收：** 在练习仓库完成“修改文件→查看diff→暂存→提交→查看log→创建并切换分支”的完整操作，并能解释每一步改变了哪个区域。

### 2.2 GCC构建链

**简历候选表述：** 与CMake合并写为`使用CMake/GCC完成工程配置与构建。`

**当前状态：** 知道GCC是编译器，但“把C语言转化为其他语言”的旧表达不准确。

**快速补强：**

- 预处理：展开头文件和宏，得到预处理后的源码。
- 编译：把C源码转换为汇编表示。
- 汇编：把汇编转换为目标文件。
- 链接：把目标文件、启动代码和库组合为ELF等固件。
- 了解ELF、HEX、BIN和MAP各自用于什么，不要求背所有命令选项。

**验收：** 能画出`.c → 预处理 → 汇编代码 → .o → ELF/HEX/BIN`流程，并解释编译错误与链接错误的差别。

### 2.3 CMake工程配置

**简历候选表述：** `使用CMake/GCC完成工程配置与构建。`

**当前状态：** 实际修改过源文件、头文件搜索路径和浮点格式化相关构建选项。

**快速补强：**

- `add_executable`或工程目标的作用。
- `target_sources`、`target_include_directories`、`target_compile_definitions/options`的职责区别。
- 头文件路径只影响查找，源文件仍需加入构建目标。
- CMake负责生成构建规则，GCC工具链负责实际编译与链接。

**验收：** 能用自己的工程说明“新增一个`.c/.h`文件时改哪里”“为什么头文件找到但函数仍可能链接失败”“浮点格式化支持属于哪类选项”。

### 2.4 OpenOCD、ST-Link与SWD

**简历候选表述：** `使用过OpenOCD配合ST-Link进行程序下载和调试。`

**当前状态：** 亲自使用过ST-Link；记得OpenOCD与烧录相关，但下载、调试和连接层级需要复习。

**快速补强：**

- ST-Link是硬件调试器，SWD/JTAG是调试接口，OpenOCD是主机侧调试服务。
- OpenOCD负责与目标芯片通信，并向GDB等上层工具提供调试服务。
- 烧录只写入Flash；调试还包括暂停、断点、单步、查看寄存器和内存。
- 区分OpenOCD、GDB、IDE和ST-Link各自职责。

**验收：** 能口述`IDE/GDB → OpenOCD → ST-Link → SWD → STM32`链路，并解释“能烧录但断点失败”为什么不能简单归因于Flash。

## 10. 综合仪器简历钩子快速补强

### 10.1 RTOS对象选型

- 为什么LCD用事件组而不是队列：多个界面脏区可用不同位合并通知，不需要逐条保存同类刷新请求。
- 为什么DMM用长度1覆盖队列：显示只关心最新测量值，旧值允许被覆盖；队列复制的是完整结构体而非指针。
- 为什么SPI DMA用二值信号量：任务启动异步传输后阻塞等待，完成中断GiveFromISR，任务恢复后再释放片选。

### 10.2 示波触发与采集

- 能完整复述：比较器上升沿→EXTI3→启动ADC DMA→TIM3 TRGO按节拍触发ADC→DMA搬运1024点→完成回调→事件组→LCD任务。
- 能解释Hold-Off、强制触发和One-Shot分别解决什么问题，以及为什么触发控制不等于采样时钟。
- 能计算500 kSa/s下1024点采样窗口约为2.048 ms，并说明采样率、观察时间窗和混叠的关系。

### 10.3 VREFINT与多量程

- 能写出`VDDA = 1.205 × 4095 / ADC(VREFINT)`并说明ADC测量依赖参考电压。
- 能解释常规组服务1024点示波采集，注入组以10 Hz周期测DMM/VREFINT/电源/触发阈值，注入组不使用DMA。
- 能解释GPIO挡位优先级、1k档全低默认规则、电压档倍率和电阻档1 MΩ并联修正。

### 10.4 AWG调试案例

- 低频问题：原逻辑只在采样率超过500 kHz的分支写TIM5参数，低频档没有更新PSC/ARR；修改为两条路径统一写入，并按`ARR=72 MHz/fs-1`修正计数。
- 切频滞后一档：原逻辑在更新`fWaveformFrequency`前调用设置函数，硬件加载旧频率；把调用移动到新值赋值后。
- 验证口径：两项均已编译、烧录并上板运行；能说明观察变量、TIM寄存器和示波器输出的验证顺序。
- 三角波验收门槛：把当前单调斜坡表改成前半周期线性上升、后半周期线性下降，检查首点/峰值/末点及周期拼接连续性；完成编译、烧录，并用示波器确认上升段、下降段、周期和频率后，简历才能写“输出正弦波、方波和三角波”。
- 风险边界：波形共享缓冲仍有撕裂风险；未完成双缓冲或任务化前，不在主动介绍中宣称该问题已经解决。
