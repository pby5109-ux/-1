# 面试准备：豪迈集团 · 软件工程师

> 本文件只针对本投递包（preview_id: himile-20260918-v1）。答不上来的部分宁可少说，不要顺着 JD 编。

## 一、最可能被问的 9 个问题

**1. 你这个 PC 网关是怎么做的？半帧、粘帧怎么处理？**
答：PC 端 Python 在线串口网关，流式收数据，缓存里按帧头找帧；不够 18 字节就等下一次；帧头匹配上但校验不过时只向后滑 1 字节重同步，不整段丢弃，避免刚好跨包的帧被漏掉；校验通过再解析，重复序号做有界标记。写的时候顺带做了 7 项协议/网关测试。
**边界**：缓存不持久化，ACK 不代表日志已落盘。

**2. 网关的数据存在哪里？为什么不用数据库？**（本题必答，风险最高）
答：目前只输出 JSON／CSV 日志文件，没有数据库。**如实说明**：项目里没有需要数据库的场景，我也没有数据库项目经验。
**不要**临场编造 MySQL/SQL 经验——JD 明写数据库，编了必被追问。

**3. 你优化过什么现有系统？**
答：智慧农场里三个动作：①修复队列满时动态消息未释放造成的内存泄漏；②把持续报警改成 warning/recovered 状态边沿通知，减少重复消息；③给水泵加 5% 滞回，避免临界反复启停。综合仪器里修正了低频档定时参数未更新和切频滞后一档的问题，并上板验证生效。
（这题对应 JD 第 3 条"优化、完善现有系统"，是本稿最值钱的一段。）

**4. 设备通信你会哪些？**
答：用过的有 UART、I²C、SPI，自定义过 18 字节大端遥测帧，带 CRC16-CCITT 校验、序号匹配和 ACK 有限重试；也理解 RS485 差分和电力线载波的原理。
**边界**：RS485／载波只在实习培训里学原理，没实操过；CAN、以太网没有项目经验。

**5. 为什么投软件岗，而不是纯嵌入式？**
答：我一直做的是设备侧软件——采样调度、任务划分、协议编解码、异常处理，本质是软件工作；上位机和设备通信这条线我做过网关，想往系统层和应用软件方向走。

**6. 如果让你和 PLC 或 AGV 做通信，你怎么上手？**
答：先确认物理层和参数（接口类型、波特率／校验位、地址、协议规约），再用抓包或示波器看链路上有没有实际收发，最后对着协议文档逐字段核帧结构。这套顺序是我在实习里整理出来的：供电接线 → 信号输入 → 通信参数 → 软件状态。

**7. 你写过给别人用的工具吗？**
答：PC 串口网关 + 配套的协议测试，处理半帧、粘帧、错误重同步、重复帧，输出 JSON／CSV 供分析。

**8. 遇到不熟悉的系统异常，你的排查顺序？**
答：先分层缩小范围——供电与接线、信号输入、通信参数、软件状态，每层都有可测的观察点；不靠记忆依赖默认值。

**9. 团队协作和沟通的例子？**
答：校学生会科创部部长，统筹约 50 名成员，组织过校级宣讲和 200 余人活动，现场出现过音频设备故障，按主备预案切换恢复。**注意**：本版简历没有校园栏，但被问到时可以讲，不算超范围。

## 二、需要重点复习的钩子

| 钩子 | 来自 | 要能讲清 |
|---|---|---|
| 自定义帧协议 | 低功耗节点 | 帧格式、CRC16、序号、ACK、超时与一次重传 |
| 网关重同步 | 低功耗节点 | 为什么校验失败只滑 1 字节 |
| 内存泄漏修复 | 智慧农场 | malloc → 队列 → UART DMA → free 的所有权链；Put 失败也要释放 |
| 状态边沿与滞回 | 智慧农场 | 为什么能用边沿替代持续报警、滞回上下阈值怎么选 |
| 软件分层 | 综合测量平台 | BSP／GUI／TASK 三层划分与事件组、覆盖队列、二值信号量各自用在哪 |
| 系统优化案例 | 综合测量平台 | 低频 ARR 参数未更新、切频滞后一档的定位与验证顺序 |
