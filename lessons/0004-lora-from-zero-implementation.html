从零实现STM32串口LoRa节点

目标不是背现有代码，而是知道如果工程目录是空的，应按什么顺序搭出一条可调试、可验证、可低功耗的LoRa链路，并真正理解当前每个函数为什么存在。

当前边界：本文解释当前软件设计及从零实现步骤。节点协议、网关代码、主机测试和两种固件构建已经完成；真实双模块RF、AUX、ACK时序、距离、RSSI、丢包和功耗仍等待实物验证。

1. 从零实现时不要一上来写完整状态机

最稳妥的顺序是每次只增加一个变量，并保留上一阶段的验证结果：

  1. 两块LoRa模块＋两套USB转TTL，先证明模块之间能够透明传输。
  2. STM32只用阻塞UART发送固定字符串，证明MCU→模块串口链。
  3. 加入M0/M1和AUX，证明工作/休眠模式切换。
  4. 先定义协议并在PC上验证固定测试向量，不接RF。
  5. 把传感器数据编码成18B帧，仍先使用阻塞UART发送。
  6. 把发送改成DMA＋完成回调＋超时。
  7. 增加11B ACK、NodeID/Sequence匹配和一次重试。
  8. 最后加入模块休眠和STM32 RTC Stop。
  9. 再做在线网关、去重、CSV、RSSI、距离和功耗测试。

这样出现问题时，你知道它是在哪一层首次出现，而不是同时面对模块配置、串口、DMA、协议、ACK和低功耗六类变量。

2. 第一阶段：模块硬件与AT配置

2.2 先脱离STM32配置两块模块

厂商V2手册给出的透明对传步骤是：两端进入AT模式、设置透明传输、相同LEVEL和相同信道，再重启生效。当前节点还需要打开M0/M1硬件控制：

+++                 进入AT模式
AT                  测试串口是否能收到OK
AT+HELP             保存当前完整配置
AT+MODE0            透明传输
AT+LEVEL2           初次联调先用相同LEVEL2
AT+CHANNEL01        两端使用相同信道
AT+DRSSI0           初次联调关闭RSSI尾字节
AT+SWITCH1          打开M0/M1硬件模式控制
AT+RESET            重启并让配置生效

命令以回车换行结束，所有AT字符使用大写。两块模块都配置完成后，先用串口助手互发ASCII和HEX数据。只有这一阶段通过，才接STM32。

AT+SWITCH1生效后，M0/M1不能悬空。休眠模式下不能靠普通串口数据唤醒，必须改变M0/M1。

3. 第二阶段：CubeMX和STM32外设配置

3.1 USART3

  • Asynchronous，9600 baud，8 data bits，No parity，1 stop bit。
  • TX/RX同时启用，无硬件流控。
  • PB10配置为USART3_TX复用推挽输出，PB11为USART3_RX输入。

3.2 DMA和中断

  • USART3_TX → DMA1 Channel2，Memory to Peripheral。
  • 外设地址不自增，内存地址自增，Byte对Byte，Normal模式。
  • 使能DMA1 Channel2中断和USART3全局中断。
  • 当前工程还生成了RX DMA1 Channel3，但LoRa ACK实际使用阻塞式HAL_UART_Receive()，因此当前LoRa链并没有使用RX DMA。

3.3 M0/M1/AUX有两种配置方法

推荐从零工程：在CubeMX把PA8/PA9标成GPIO_Output，PA1标成GPIO_Input，并加用户标签LORA_M0、LORA_M1、LORA_AUX。

当前工程：.ioc没有配置PA1/PA8/PA9，而是在main.h手工定义宏，并由LoraControlPins_Init()运行时配置。这样LoRa专用引脚只在LoRaDebug构建中启用，不影响默认BLE构建。两种方式选一种即可，不需要重复初始化。

3.4 RTC Stop属于最后阶段

先把通信闭环跑通，再配置LSE、RTC Alarm、EXTI17和Stop。否则“收不到ACK”与“醒后时钟没恢复”会混在一起。当前工程使用LSE 32.768kHz和RTC Alarm，退出Stop后重新执行SystemClock_Config()并恢复SysTick。

4. 代码为什么分成三层

main.c：我这轮要发送什么、报警了吗、睡多久 ↓ lora_node.c：如何唤醒模块、发送、等ACK、重试、休眠 ↓ lora_protocol.c：结构体怎样变成固定字节，字节怎样校验和解析 ↓ HAL UART / DMA / GPIO：真正操作STM32硬件
文件应该知道什么不应该知道什么
lora_protocol.cMagic、字段偏移、大小端、CRC、遥测与ACK格式不应该知道UART、GPIO、AUX和休眠
lora_node.cUART句柄、M0/M1/AUX、超时、重试、Sequence不负责采集AHT20或绘制OLED
main.c传感器、阈值、Flags、LED和RTC周期不应该手工填写每个帧字节或重复实现CRC

这条分层的价值是：协议层可以在PC上做纯单元测试；换UART或换MCU只主要影响节点层；以后增加第二种传感器不需要改CRC实现。

5. lora_protocol.h：先定义“合同”

头文件定义通信双方必须共同遵守的规则：

  • Version=1，Telemetry类型0x10，ACK类型0x11。
  • Flags的bit0/1/2分别表示AHT、光照、雨滴有效，bit7表示报警。
  • 遥测固定18B，ACK固定11B。
  • LoraTelemetry_t保存业务字段，LoraAck_t保存确认字段。

结构体只是程序内部的语义对象，不能直接memcpy到串口，因为编译器可能插入填充字节，而且CPU大小端和接收端平台可能不同。必须显式编码。

6. lora_protocol.c逐函数解释

6.1 WriteU16Be()

destination[0] = value >> 8;  // 先写高8位
destination[1] = value;       // 再写低8位

作用是把16位整数明确写成大端序。例如0x1234在线上发送12 34。它是static，因为只供本文件内部编码函数使用。

6.2 ReadU16Be()

value = (source[0] << 8) | source[1];

执行相反操作，把两个大端字节重新拼成16位整数。温度字段拼好后再转成int16_t，才能恢复负数补码。

6.3 HasValidHeaderAndCrc()

这是所有解码函数共用的入口检查：

  1. 指针非空，长度至少能包含头和CRC。
  2. Magic必须为A5 5A。
  3. Version必须等于当前版本。
  4. Type必须等于调用者期望的Telemetry或ACK。
  5. 读取末尾2B CRC，重新计算前面全部字节并比较。

6.4 LoraProtocol_Crc16Ccitt()

使用初值0xFFFF、多项式0x1021，逐字节、逐位更新16位CRC。它只负责计算，不知道这段数据是遥测还是ACK。

6.5 EncodeTelemetry()

把LoraTelemetry_t按固定偏移写入18B数组，最后对前16B计算CRC并写入索引16～17。输入检查capacity是为了避免调用者数组过小导致越界。

6.6 DecodeTelemetry()

先要求长度严格等于18B，再校验头和CRC，然后把各字段读回结构体。节点当前主要发送遥测；这个函数主要供C端接收器、测试或未来网关使用。

6.7 EncodeAck()与DecodeAck()

ACK是另一种固定11B帧：Magic、Version、Type、NodeID、Sequence、status、CRC。网关编码ACK，节点解码ACK。节点必须继续比较NodeID、Sequence和status，不能只看CRC通过。

7. lora_node.h：把硬件依赖和运行状态分开

7.1 LoraNodeStatus_t

它不是单纯返回成功/失败，而是区分参数错误、模式超时、UART启动失败、UART发送超时、UART硬件错误、ACK超时和ACK非法。这样调试时能知道链路断在哪一层。

7.2 LoraNodeConfig_t

配置结构体把所有“因板子或部署而变化”的内容集中起来：

  • UART句柄；
  • M0/M1/AUX端口和引脚；
  • NodeID和初始Sequence；
  • 模式、UART、ACK超时；
  • 最大业务重试次数。

这是一种依赖注入：lora_node.c不把USART3和PA8写死，所以理论上可以换UART或换引脚。LoraNode_Init()会把整个配置复制进节点对象，因此main.c中的局部lora_config离开作用域后不会悬空。

7.3 LoraNode_t

节点对象保存三类运行状态：已经复制的配置、下一帧Sequence、是否初始化成功。它相当于一个小型设备实例。

8. lora_node.c逐函数解释

8.1 三个静态变量

static volatile bool tx_complete;
static volatile bool tx_error;
static UART_HandleTypeDef *active_uart;

DMA/UART完成发生在中断回调，主流程在等待标志，所以两个标志必须是volatile。active_uart用于确认回调确实属于当前LoRa发送，而不是同名HAL回调中的其他UART。

8.2 WaitAuxIdle()

循环读取AUX。该模块定义AUX高为忙、低为完成，因此看到低电平才返回成功。它同时使用mode_timeout_ms防止模块断线或异常时永久卡死。

当前是裸机忙轮询，等待期间CPU没有去执行其他工作；若以后追求更深低功耗，可用EXTI或定时状态机改造，但当前先保证逻辑简单可验证。

8.3 SetHardwareMode()

统一完成三步：写M0、写M1、等待1ms后检查AUX。这样调用者不会忘记模式切换后的稳定过程。

8.4 WakeRadio()和SleepRadio()

它们只是带语义名称的薄包装：

WakeRadio  → M0=0, M1=0 → 高时效模式
SleepRadio → M0=1, M1=1 → 休眠模式

这两个函数成立的前提是模块已经执行并保存AT+SWITCH1。

8.5 TransmitDmaAndWait()

这是“可靠启动一次STM32 UART发送”的函数，不负责RF ACK：

  1. 清空完成/错误标志，并登记当前UART。
  2. 调用HAL_UART_Transmit_DMA()。
  3. 若HAL返回BUSY，最多间隔2ms尝试3次。
  4. 若仍不是HAL_OK，返回UART_START_ERROR。
  5. 启动成功后等待中断回调改变tx_complete或tx_error。
  6. 超过uart_timeout_ms则Abort并返回UART_TIMEOUT。
两个重试层不要混：这里的3次只是在本地UART为BUSY时重新尝试“启动DMA”；max_retries=1则是完整数据帧没有收到ACK时的RF业务重发。它们不是同一个概念。

8.6 LoraNode_Init()

先检查所有必需指针和超时是否有效，然后复制配置、设置初始Sequence，并尝试让模块进入休眠。只有休眠模式切换成功才把initialized置真。

当前main.c把返回值强制忽略，这是一个已知薄弱点；从零写时应检查返回值并显示或记录初始化错误。

8.7 LoraNode_SendTelemetry()

这是节点层的总编排函数：

检查initialized → 用参数建立LoraTelemetry_t → EncodeTelemetry生成18B → WakeRadio → 循环：等AUX→DMA发送→阻塞收11B ACK→解码和匹配 → 成功则退出；失败则按max_retries重试 → Sequence加1 → SleepRadio → 返回最具体的状态码

frame和ack_frame是函数栈上的局部数组，但函数在DMA完成前不会返回，因此发送期间内存仍有效。整次调用的重试使用同一份frame，所以Sequence相同。

8.8 LoraNode_SelectSleepSeconds()

根据报警状态返回10秒或30秒。它其实是项目策略而非纯硬件驱动；当前放在节点模块中便于集中LoRa策略。若以后多个应用共用驱动，可以把该函数移动到应用层。

8.9 两个OnUart回调

HAL的全局回调在main.c中接收中断结果，然后转发到节点模块：

DMA1_Channel2_IRQHandler
→ HAL_DMA_IRQHandler
→ HAL内部UART完成流程
→ HAL_UART_TxCpltCallback
→ LoraNode_OnUartTxComplete
→ tx_complete=true
→ TransmitDmaAndWait退出等待

错误路径类似，只是设置tx_error=true。回调里只改标志，不做CRC、ACK或长时间阻塞。

9. main.c怎样把所有模块串起来

9.1 双构建

CMake选项SENSOR_COMMUNICATION_LORA默认关闭。普通Debug保持BLE路径，LoRaDebug把该宏设为1，编译LoRa分支。这样新增功能不会直接破坏原项目。

9.2 初始化

main.c创建LoraNodeConfig_t，提供USART3、PA8/PA9/PA1、NodeID=1、初始Sequence=0、模式超时100ms、UART超时500ms、ACK超时300ms和一次业务重试。然后初始化控制引脚并调用LoraNode_Init()。

9.3 每轮业务

  1. 采集AHT20、BH1750和雨滴。
  2. 根据读取返回值建立valid位，根据阈值建立alert位。
  3. 温湿度乘10转成定点数，避免在线上传输float。
  4. 调用LoraNode_SendTelemetry()。
  5. 根据传感器状态和通信状态控制LED。
  6. 正常30秒、异常10秒进入RTC Stop。

10. PC网关为什么也要写代码

LoRa模块只把收到的RF字节从UART输出，它不会理解18B业务协议，也不会自动生成本项目ACK。PC程序负责：

  1. 串口收到多少字节就先放入缓存，不能假设一次read就是一帧。
  2. 搜索A5 5A，凑足18B，再检查Version、Type和CRC。
  3. 解析NodeID、Sequence、Flags和传感数据。
  4. 生成匹配的11B ACK并优先写回串口。
  5. 用NodeID＋Sequence判断重复，最后写CSV和日志。

当前TelemetryStreamDecoder处理拆包、粘包和错位；DuplicateTracker限制1024项；GatewayProcessor把解析、去重和ACK组合成事件；run_serial_gateway()负责真实COM循环。

12. 当前源码的已知改进点

  • main.c应处理LoraNode_Init()失败。
  • 最终SleepRadio()失败不应完全忽略，否则可能带来高功耗。
  • ACK当前固定阻塞接收11B，没有节点侧流式重同步。
  • 300ms要按真实LEVEL和往返时序重新确定。
  • RX DMA1 Channel3当前没有被LoRa ACK路径使用，不能说收发都采用DMA。
  • Sequence掉电归零，网关近期去重缓存可能与新会话冲突。
