STM32F103 RTC Alarm + Stop低功耗

目标：不靠背函数名，能够从电源域、时钟域、中断链和当前源码四个角度解释“为什么能睡、为什么能醒、醒后为什么必须恢复时钟”。

一句话模型

Stop模式关闭CPU主执行时钟、HSE/PLL等高速时钟，并让内部稳压器进入低功耗状态；SRAM和大多数寄存器仍供电保留。独立的LSE继续驱动RTC，Alarm匹配后经EXTI17和NVIC唤醒Cortex-M3。

1. 三种低功耗模式不要混讲

模式停了什么保留什么唤醒后适用
SleepCPU内核执行外设时钟、SRAM、寄存器继续执行，延迟最低短等待
StopCPU与高速时钟，PLL/HSE/HSI关闭SRAM、寄存器、RTC/备份域从WFI后继续，但SYSCLK先回到HSI，必须重建时钟树本项目5秒周期休眠
Standby1.8V域和内部稳压器主要只剩备份域类似复位启动，SRAM丢失更长休眠、最低MCU功耗

2. 当前工程的完整信号链

LSE 32.768 kHz → RTC预分频为1 Hz → RTC 32位计数器每秒加1 → ALARM = 当前计数 + 5 → 计数匹配，RTC置ALRAF → RTC Alarm路由到EXTI Line 17 → EXTI17向NVIC提出RTC_Alarm_IRQn → Cortex-M3退出WFI并执行RTC_Alarm_IRQHandler → 中断返回到HAL_PWR_EnterSTOPMode()之后 → SystemClock_Config()恢复HSE×9 PLL = 72 MHz → HAL_ResumeTick() → 进入下一轮采集

3. Enter_Stop_Mode()逐段含义

  1. 读取RTC->CNTH/CNTL，计算绝对闹钟值cnt + seconds。
  2. 等待RTOFF，进入RTC配置模式，写ALRH/ALRL后退出配置模式。
  3. 使能RTC Alarm中断、EXTI17中断与上升沿。
  4. 清PWR唤醒标志，避免旧标志干扰本次睡眠。
  5. HAL_SuspendTick()只关闭SysTick中断使能；并不是把5秒交给SysTick计时。
  6. HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI)清PDDS、置LPDS、置SLEEPDEEP并执行WFI。
  7. Alarm中断唤醒后，代码从WFI之后继续；先恢复PLL和72MHz系统时钟，再恢复SysTick中断。
  8. 清Alarm/EXTI标志并关闭本次Alarm中断，为下一轮重新设置做准备。
SysTick常见误区：进入真正的Stop后，主时钟已停止，SysTick不会靠72MHz继续完整计时。暂停SysTick的主要目的，是避免进入Stop前后恰逢一个pending tick导致睡眠被打断或立即返回；5秒计时来自LSE驱动的RTC。

4. WFI与中断的关系

WFI表示Wait For Interrupt。它不是死循环，也不是软件延时，而是告诉Cortex-M3：当前没有工作，直到符合条件的中断到来再恢复。Alarm发生后，CPU先进入RTC中断服务函数；中断返回后，继续执行WFI之后的代码。

现行ISR直接调用HAL_RTC_AlarmIRQHandler()清理RTC Alarm和EXTI17挂起标志；旧版rtc_alarm_wakeup没有被主循环读取，已删除。CPU被唤醒依靠硬件RTC→EXTI17→NVIC链。

5. 为什么醒后必须重新配置72 MHz

STM32F1退出Stop时自动选择HSI作为SYSCLK，而睡前工程使用HSE 8MHz经PLL×9得到72MHz。若不调用SystemClock_Config()，CPU、APB、定时器和USART会在与原设计不同的时钟下运行，串口实际波特率、定时器周期和延时都会偏离。

正确顺序：Alarm唤醒 → ISR清标志 → 回到WFI之后 → 恢复HSE/PLL/总线分频 → 恢复SysTick → 继续业务。

6. 当前工程的实际周期

代码设置的是“睡5秒”，不是“每5秒采样一次”。真实采样周期约为：

T周期 = T采集 + T显示 + T判断 + T串口发送 + 5秒Stop

AHT20测量本身约75～100ms，OLED和9600波特率状态发送也需要时间，所以相邻两轮采样间隔一定大于5秒。若要求严格每5秒采样，应根据RTC绝对时间安排固定截止点，而不是每轮完成后再睡5秒。

7. MCU低功耗不等于整板低功耗

当前代码没有关闭OLED、蓝牙模块、AHT20和BH1750的供电，也没有熄屏。即使STM32已经进入Stop，外部模块仍可能主导整板电流。调试器的DBG_STOP设置、ADC/DAC使能和悬空GPIO也会影响实测。

  • 先测运行态整板电流。
  • 确认GPIO指示出进入Stop，再测Stop阶段电流。
  • 分别断开OLED、蓝牙和传感器，定位主要耗电源。
  • 不要用“程序能5秒后醒来”代替电流测试；前者验证功能，后者才验证低功耗效果。

8. 上板验收清单

  1. 烧录当前dab9a91对应固件，确认OLED与状态蓝牙TX仍工作。
  2. 确认手机发送GET/SET没有响应，且固定阈值判断仍正常。
  3. 用GPIO翻转或串口时间戳观察：每轮业务完成后约5秒再醒。
  4. 醒后串口仍为9600且数据不乱码，证明时钟恢复成功。
  5. 测运行态和Stop阶段整板电流，记录数值；若差异小，逐个排查OLED/蓝牙/传感器和调试保持。
  6. 重复至少20轮，确认没有首轮正常、后续不醒或周期漂移异常。

11. 2026-08-27 LoRa构建增量

上文5秒链路对应默认BLE构建。当前LoRaDebug源码使用正常30秒、异常10秒Stop；发送链先切M0/M1为00并等待AUX，再完成UART DMA、ACK和重试，结束后切M0/M1为11并再次等待AUX，随后才设置RTC Alarm并进入MCU Stop。

30秒是当前可编译的软件策略，不等于最终部署最优值。对于温室或校园试验田的慢变化环境，可以把正常周期设计为5～10分钟、异常周期缩短到10～30秒；在代码实际修改和上板验证前，应称为优化方案。

Iavg(30s)  = (200mA×0.2s + 20mA×0.8s + 0.1mA×29s) / 30s  ≈ 1.963mA
Iavg(300s) = (200mA×0.2s + 20mA×0.8s + 0.1mA×299s) / 300s ≈ 0.286mA

12. 外设断电必须发生在WFI之前

完成通信并等ACK → LoRa切11并等AUX → OLED熄屏 / 传感器Power Down → 总线GPIO切安全状态，避免反向供电 → 负载开关或P-MOS关闭外设VCC → 设置RTC Alarm → MCU执行WFI进入Stop RTC唤醒 → 恢复HSE/PLL与SysTick → 打开外设VCC → 等待上电稳定并重新初始化 → 开始下一轮采集

当前工程没有为OLED、AHT20、BH1750和雨滴板定义独立电源使能GPIO，也没有源码证据表明板上已有负载开关。因此现阶段只能使用器件待机命令；真正硬断电需要补充电源开关电路和控制引脚。外设VCC关闭时，MCU通信引脚若仍输出高电平，可能经外设保护二极管反向供电。

14. AHT20自动休眠与GPIO电源门控

AHT20手册纠正：表2给出3.3V下休眠电流典型0.25µA、测量电流典型23µA；表10规定Busy Bit7=0时设备空闲并处于休眠状态。当前驱动完成0xAC测量并确认Busy清零后，AHT20会自动回到非测量低功耗状态，不需要额外Sleep命令。

GPIO不能直接承担模块VCC电流，也不能软件切断已经直接连接的公共3.3V铜线。真正的电源门控需要增加高边P-MOS或专用负载开关：

3V3_ALWAYS → 高边P-MOS / Load Switch → VPERIPH受控电源域 → OLED、传感器或模块VCC STM32 GPIO → 只控制MOS栅极或Load Switch EN

高边开关让外设与MCU保持公共地，适合I2C和ADC。低边切GND会改变外设地参考并增加通信、ADC误差与反向供电风险，通常不作为本项目首选。如果模块已经直连公共3.3V，必须改线或增加转接板，现有GPIO不能凭空把它关掉。

共享I2C的额外限制：OLED和AHT20共享I2C1。若只切断OLED VCC，而SDA/SCL上拉仍由AHT20的常供电域保持高电平，OLED仍可能从I/O脚被反向供电。工程上应在“二者整组断电”“增加总线隔离”“OLED仅熄屏不断电”之间选择，并通过整板电流实测决定。

15. 当前接线不改动时的可行方案

用户确认雨滴模块当前只能连接板上公共电源，现有硬件没有电源门控。此时软件无法切断雨滴板VCC，但雨滴读取函数已经在每次读数后调用HAL_ADC_Stop()，所以Stop期间ADC本身不持续转换；持续耗电来自仍然上电的模块电路。

睡前： LoRa切11并等待AUX → AHT20测量完成后自动休眠 → OLED Display Off → BH1750发送0x00 Power Down → RTC Alarm → STM32 Stop 醒后： 恢复系统时钟与SysTick → OLED Display On / 必要时刷新显存 → BH1750发送0x10 → 等待首轮转换 → 读取传感器并发送

其中OLED Off和BH1750 Power Down尚未接入当前主循环，仍是待实现方案。没有整板电流实测前，应称为“现有硬件接线下可实现的更低功耗方案”，不能宣称为绝对最低功耗。
