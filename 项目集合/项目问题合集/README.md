## 面试训练方式

接收用户提供的简历、面试官身份、公司、背景和岗位 JD，据此提问并根据回答追问。公司信息需要时查证，不虚构岗位要求或个人经历。

用户要求后续语音训练持续保持较慢、平稳的语速；使用短句，每次只问一个明确的问题，给用户充分思考和作答时间。

已经清楚回答的同一问题不重复追问；继续考查新边界时说明区别，不让用户反复复述已讲清的机制。面试官的重复提问不算用户错误，也不创建问题记录。

项目资料按实际问到的内容再补读、核对，无需每次提前通读三个项目全部材料。

每轮训练结束，只将确认存在的硬性错误写入本目录。硬性错误包括事实、原理、技术机制或项目实现理解上的实质错误；先通过追问和资料核对了解清楚，再记录正确说法及具体错误点。仅有表达不顺、重复、停顿、口误或组织顺序不清时，只帮助调整说法，不记录。回答尚未展开、信息不足或单纯有疑问时，先澄清，不直接算作错误。已经熟练且回答正确的内容不重复记录；没有确认的硬性错误时无需新增问题文件。

## 简洁纠错格式

每条问题的正文仅保留以下两部分：

1. 正确说法：清楚、简短地说明正确概念或正确回答，必要时补充适用条件或简短资料依据。
2. 错误点和理解偏差：用简短条目列出已确认的事实错误或理解错误。证据不足时先核实，不将单纯表达不顺、疑问或未展开内容记为错误。

不要求长篇原因分析、完整回答转录或额外复练题。只记录实际发生的问题，不虚构用户原话、源码实现、测试结果、数值或个人贡献。

如需修正此前记录，直接更新正确说法和错误点；有必要保留纠错依据时用一句话说明，避免展开复杂表格。

## 文件组织与接续

- 问题索引.md：问题编号、主题、状态和文件链接。
- 问题记录/：按问题保存 Markdown 文件，使用问题记录模板.md；编号从 Q-0001 递增且不复用。
- 训练复盘/：仅在需要时保存简短的本轮问题索引，不重复抄写各条纠错内容。

同一知识点再次出错时更新原记录，不重复建档。状态使用“待纠正、待复测、已掌握”；已掌握的问题保留历史、退出待练清单，再次出错则重新打开。

本聊天后续训练遵循以上规则。更换聊天时提供本目录，先读取 README.md 和问题索引.md，再按需读取问题记录及项目参考；不假定新聊天自动继承上下文。简历、JD 和面试背景以用户本轮提供的版本为准。
