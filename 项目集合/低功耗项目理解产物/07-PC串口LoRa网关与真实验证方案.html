接收完成以后：现有存储与产品化边界（2026-09-17）

历史版本ede4039曾支持--csv 文件路径导出普通数据，现行版本已删除此参数。当前链路是串口流式组帧→校验18字节帧→标记重复→先返回11字节ACK→打印JSON；仅传感有效位无效时自动追加故障CSV。网关记录的带时区本机received_at不是节点采集时间；异常值为−1必须结合flags，JSON另有sensor_errors。

重复合法帧也回ACK、也打印，并标记duplicate=true；若它含传感故障，还会再次写入故障CSV，普通重复帧不写故障CSV。1024项RAM缓存不跨程序重启保存。现有程序没有数据库、历史图表、推送报警、掉线判断或自动串口重连。ACK发生在写CSV之前，进程或存储此时失败会导致节点以为已接收而网关未保存。串口flush不是CSV落盘保证。

最小可用产品路线（建议，尚未实施）

  1. 本地SQLite事务存储：记录数据、有效性、网关时间；需要补传时增加采集时间、启动会话标识，并为业务记录设计唯一键。原始接收日志可留重复帧，业务表去重，避免重复报警。
  2. 明确ACK语义：若要求确认即已接管数据，先可靠本地持久化再确认，并实测调整ACK窗口；不要等待云端网络再ACK。存储满/失败不能谎报成功。
  3. 简单界面：最新有效值、更新时间、传感故障、节点在线状态和历史趋势；故障−1不能绘制为正常测量值。
  4. 报警分开：环境越界、传感器故障、节点失联，加入恢复通知和抑制重复。15分钟上报节点可考虑连续错过3次加容差为掉线示例，不是当前代码。
  5. 无人值守：串口掉线有限退避重连、读写超时、程序自启动/异常恢复、日志轮转、磁盘满保护、备份与可观察健康状态。
  6. 部署验收：拔串口、杀进程、网关断电、节点重启、ACK丢失、磁盘满、传感器断线与长期运行；硬件再验证防水/结露、电源、ESD、天线与安装。对外销售时核对目标地区无线和产品合规要求，不把模块合规等同整机合规。

CRC仅用于检错，不等于加密或身份认证；联网/远程控制需要身份鉴别、密钥管理与防重放。多节点和云端按需求增加，单节点现场监测不必先做复杂平台。

一手参考：SQLite事务与原子提交、pySerial超时与异常接口。数据库可靠性仍依赖配置与存储硬件。可继续追问“为什么收到ACK仍可能丢数据”。

PC串口LoRa网关与真实验证方案

目标：能回答“电脑怎样返回ACK”和“没有模块时能证明什么”，并为以后实物测试留下可执行步骤。

1. 电脑可以直接作为网关

网关LoRa模块 TX/RX ↕ 3.3V UART USB转TTL ↕ USB虚拟COM口 Python网关程序

不需要额外单片机。PC通过USB转TTL打开COM口，读取模块输出的18字节遥测帧，调用现有协议解析函数，然后把11字节ACK写回同一串口。

2. 串口助手和Python的边界

方案适合不足
普通串口助手观察十六进制、手工发送固定ACK、检查波特率通常不能自动解析CRC和动态复制NodeID/Sequence
支持脚本的串口工具快速原型和简单自动应答脚本接口依赖具体软件，项目可移植性较差
Python＋pyserial持续收帧、CRC、动态ACK、日志、丢包率和RSSI统计需要编写流式缓存和异常恢复
网关MCU脱离PC长期运行需要额外硬件、固件和上行网络接口

3. Python在线网关应怎样工作

打开COM口：9600、8N1
while running:
    读取当前可用字节，追加到接收缓存
    在缓存中寻找 A5 5A 帧头
    不足18字节则继续等待
    取18字节并校验版本、类型和CRC
    解析 NodeID、Sequence 和传感器数据
    检查 (NodeID, Sequence) 是否重复
    生成匹配的11字节ACK
    serial.write(ack)
    输出JSON；若传感器有效位无效，追加故障CSV

不能假设一次read()正好得到18字节：串口可能拆成多段，也可能一次返回多帧，因此必须维护字节缓存、搜索帧头并处理错位。

4. 实物连接容易踩的坑

  • 模块通信IO是3.3V电平，不要把5V TTL直接接入。
  • 模块典型供电为5V且发射存在较大脉冲电流，不要默认USB转TTL板的弱电源脚足够；单独供电并共地。
  • 节点和网关必须同信道、同速率等级、同透明模式和兼容密钥配置。
  • 两端都要接匹配频段天线，避免无天线高功率发射。
  • 网关长期供电，可保持高时效接收；节点才在发送后切到休眠。

5. 300ms ACK窗口怎样验证

用逻辑分析仪同时观察节点UART TX/RX和AUX，并让PC日志记录高精度时间戳：

t0：节点开始UART发送 t1：节点TX完成回调 t2：节点AUX发送完成 t3：网关PC收到完整18字节 t4：PC写出11字节ACK t5：节点收到完整ACK

统计t5-t0的最大值、平均值和高分位，再加安全余量设置超时。默认2148bps时，18B和11B纯净荷载位时间已占约108ms，尚未计前导码、编码、模块缓存和收发切换，所以300ms只能称初始设计值。若使用336bps，29B净荷载本身已约690ms，300ms显然不够。

6. AUX怎样验证

  1. M0/M1由11切00，观察AUX是否先高后低。
  2. 节点向模块写入18字节，观察AUX发送期间的高电平脉宽。
  3. 网关发ACK，观察节点模块接收前后AUX变化。
  4. 把逻辑分析仪时间轴与PC日志和Sequence对应，不能只看LED。

AUX低只表示模块当前发送、接收或模式切换完成，不表示远端应用必然收到；匹配ACK才是端到端证据。

7. 距离、RSSI和丢包率

指标真实测试方法
距离固定天线、功率、信道、速率、高度和方向，按10/50/100/300m等点位逐步测试并记录环境
丢包率每点发送N帧，用Sequence统计唯一收到数；区分首发成功、重试成功、最终失败
RSSI开启模块数据包RSSI后，接收帧末会附加RSSI字节；按手册公式换算并与Sequence记录
延迟记录t0～t5，分别统计UART、模块发送、网关处理和ACK回程

测试时至少记录：日期、环境、遮挡、距离、天线高度、速率等级、发射功率、总帧数、首发成功、重试成功、失败数和RSSI分布。

8. 功耗怎样验证

没有电流分析仪时，万用表只能粗看稳定电流，难以捕捉短暂发射峰值。可靠方法是电流分析仪，或采样电阻＋示波器记录电压波形：

传感器采集电流 → OLED刷新 → LoRa唤醒 → 发射峰值 → 等ACK → 模块休眠 → MCU Stop

最终应报告每个状态的电流与持续时间，再用Iavg=Σ(I×t)/T计算平均电流，而不是只引用芯片或模块手册中的休眠电流。
