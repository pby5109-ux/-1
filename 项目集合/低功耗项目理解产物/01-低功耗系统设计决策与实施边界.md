# 低功耗系统设计决策与实施边界

> 版本：2026-08-26 初版  
> 对应源码：`D:\APP\project_practice\sensor_project\sensor.design`  
> 定位：先确定可讲清、可实现、不虚构测量数据的整机低功耗方案，再决定最小代码修改。

## 1. 项目当前真实状态

- STM32F103C8T6使用RTC Alarm每轮唤醒，业务完成后进入Stop，当前休眠参数是5秒。
- 每轮依次采集AHT20、BH1750和雨滴模块，刷新OLED，进行固定阈值判断，经USART3 TX DMA发送状态，然后进入Stop。
- Stop醒后执行`SystemClock_Config()`恢复HSE+PLL 72MHz，这条MCU唤醒链已经存在。
- 当前代码没有在Stop前管理OLED、BH1750、雨滴模块和DX-BT24的功耗状态。
- 当前应用只使用蓝牙透传的TX状态上报，远程阈值修改已停用，因此不需要为了“随时收命令”而保持MCU长期运行。
- 传感器源码仓库当前`master`与`origin/master`都在`dab9a91`；已有用户改动`Core/Inc/i2c.h`，本阶段不触碰。

## 2. 最终设计目标

本项目不定义为“追求手册中最低的某个电流数字”，而定义为：

> 一个可被手机发现、定期采集环境数据、异常时提高响应速度、空闲期让MCU和可休眠外设同时降功耗的传感器节点。

“功能依旧”的具体验收含义：

1. 每次唤醒后仍能得到有效温湿度、光照和雨滴数据。
2. 阈值判断和红绿LED结果不变。
3. 手机连接蓝牙后，能在下一采样周期收到状态。
4. OLED在活动窗口显示最新数据，休眠期间可熄屏。
5. RTC能连续唤醒，唤醒后UART、I²C和ADC时序正常。

## 3. 推荐方案：可发现的自适应低功耗节点

### 3.1 采样周期不再固定为5秒

- 正常模式：30秒采集一次。温湿度、环境光和降雨状态通常不需要5秒刷新。
- 异常模式：10秒采集一次，用于更快判断是否恢复正常。
- 可选调试模式：5秒，便于上板观察，不作为长期低功耗配置。

这种方案的含金量不在于“把5改成30”，而在于把响应延迟和平均功耗变成可解释的系统策略。

### 3.2 一轮完整时序

```text
RTC Alarm唤醒
→ 恢复72MHz系统时钟和SysTick
→ 唤醒/启动本轮需要的外设
→ AHT20触发测量，BH1750单次高分辨率测量，雨滴ADC采样
→ 检查各驱动返回状态，失败时保留上次有效值但valid=0
→ 刷新OLED并在活动窗口显示
→ 阈值判断，决定下一周期为30s或10s
→ 蓝牙已连接时用UART DMA上报，未连接时不做无意义透传
→ 等待DMA真正完成或有限超时
→ OLED Display OFF，BH1750已自动Power Down，LED熄灯
→ 清标志、设置RTC Alarm、暂停SysTick
→ STM32进入Stop
```

## 4. 每个器件应该怎么睡

| 器件 | 当前状态 | 推荐策略 | 原因与边界 |
|---|---|---|---|
| STM32F103 | RTC Alarm + Stop | 保留Stop，正常30s/异常10s | SRAM/寄存器保留，RTC可唤醒；醒后必须恢复PLL时钟 |
| AHT20 | 每轮触发测量 | 保持供电，不必为它增加独立断电 | 手册给出典型休眠0.25µA，测量后Busy=0时已处于休眠；断电反而要每次等待40ms并重做初始检查 |
| BH1750 | 0x10连续高分辨率 | 改为`0x01 Power On → 0x20 One-Time H-Res → 等待最长180ms → 读数`；测量后自动Power Down | 环境节点只需要每轮一个新值，没必要在Stop期间持续转换 |
| CH1116 OLED | 整个Stop期间仍点亮 | Stop前`0xAE`进入Power Saver，醒后`0xAF`恢复；如显式控制DC-DC，用CH1116的`0xAD + 0x8A/0x8B` | 手册说明Display OFF会停振荡器、DC-DC和OLED驱动，并保留显存 |
| 雨滴YL-83模块 | 始终供电 | 第一阶段先保持；第二阶段可用负载开关/P-MOS上电后预热、采样、再断电 | 常见模块上的比较器和指示LED可能比MCU Stop耗电更大；不能用MCU GPIO直接给整个模块供电 |
| DX-BT24 | 默认正常模式 | 用`AT+PWRM0`低功耗模式，广播间隔先设3s（`AT+ADVIB`），保持可发现/可连接 | 未连接时只保留广播且UART等接口关闭；连接后所有接口恢复 |

### 已发现的OLED源码风险

当前`OLED_Init()`明确按CH1116使用`0xAD/0x8B`启动DC-DC，但`OLED_DisPlay_On/Off()`使用了`0x8D/0x14/0x10`这组不与CH1116手册匹配的指令。因此不能直接宣称现有关屏函数已经可靠降功耗。实施时应改成：

```text
最小方案：休眠前发0xAE，唤醒后发0xAF。
显式泵控：休眠前0xAE → 0xAD → 0x8A；
            唤醒后0xAD → 0x8B → 0xAF。
```

## 5. DX-BT24的推荐用法

### 5.1 为什么不推荐默认用冬眠模式

`AT+PWRM2`冬眠的手册电流最低，但关闭广播，手机无法发现或连接，并需要RST低脉冲唤醒。这会改变节点的可连接性，与“功能依旧”冲突。冬眠更适合“每隔几小时才唤醒一次、不需要手机随时连接”的节点。

### 5.2 AT配置顺序

AT命令需在蓝牙未连接时执行，默认9600、8N1。推荐用USB-TTL配置一次：

```text
AT              # 先确认串口和AT模式
AT+ADVI          # 查询广播间隔
AT+ADVIB         # B = 3000ms，先用平衡档
AT+POWE          # 查询发射功率
AT+POWE9         # 0dBm作为起点，实际距离完成后再尝试降低
AT+PWRM0         # 最后执行：进入低功耗并关闭未连接时的UART
```

`AT+PWRM0`应放在最后，因为未连接时进入低功耗后，模块外设接口已关闭，不能继续指望UART处理后续AT命令。

配置后的逻辑是：

- 手机未连接：模块低功耗广播，MCU发往UART的透传数据没有接收者，可以直接不发。
- 手机连接：蓝牙自动回到全功能状态，下一轮UART DMA可正常透传。
- 手机断开：模块自动再进入低功耗。

如要让MCU知道“现在值不值得发串口”，可将DX-BT24的`LINK-STATUS`引脚接到MCU输入：低=未连接，高=已连接。这是推荐的一根新连线，但必须先确认实际板上空闲GPIO，不能凭空指定。

## 6. 是否需要真正给外设断电

### 第一阶段：不改PCB也能做

- AHT20保持供电并使用自身休眠。
- BH1750使用单次测量后自动Power Down。
- OLED使用CH1116 Display OFF/Power Saver。
- DX-BT24使用PWRM0和更长广播间隔。
- STM32 Stop前关闭不必要LED，必要时de-init ADC/I²C/UART或至少关闭时钟。

### 第二阶段：增加供电域

如硬件允许，用专用负载开关或P沟道MOS管切断高端供电，不要让MCU GPIO直接承担模块电流。断电后还要防止信号线反向灌电：

- 蓝牙手册明确要求：切断VBAT后，MCU连到模块的所有IO都配成下拉。
- 断电的I²C器件不能继续由SCL/SDA高电平反向供电；应在断电前设置为模拟输入/无上拉，或将上拉与被控供电域一起切断。
- 重新上电后不能直接读数：AHT20需要上电稳定/初始检查，BH1750需要启动新测量，OLED需要重新初始化。

由于AHT20休眠电流已非常低，第二阶段优先切断雨滴模块等板级耗电，而不是为AHT20增加复杂开关。

## 7. 平均功耗怎么讲

不能只说“Stop很省电”，要用占空比模型：

```text
Iavg = (Iactive × tactive + Isleep × tsleep) / (tactive + tsleep)
```

降低平均电流有两个方向：

1. 降低`Isleep`：让OLED、BH1750和蓝牙与MCU一起进入低功耗，必要时切断模块供电。
2. 提高休眠占比：不在一轮中重复初始化、不向未连接的蓝牙发无意义数据，并把正常采样间隔改为30秒。

无电流仪时可以验证状态机和功能，但只能表述为“根据手册电流和活动占空比预期降低平均功耗”，不能给出实测倍数。

## 8. 代码结构建议

不把低功耗顺序散落在`main.c`中，而是设置一个小而深的`low_power`/“电源策略”模块：

```c
typedef enum {
    LOW_POWER_PROFILE_NORMAL,   /* 30s */
    LOW_POWER_PROFILE_ALERT     /* 10s */
} LowPowerProfile;

HAL_StatusTypeDef LowPower_PrepareAndEnter(LowPowerProfile profile);
HAL_StatusTypeDef LowPower_ResumePeripherals(void);
```

主循环只决定“正常还是报警”，模块内部隐藏OLED关闭、BH1750状态、RTC Alarm、SysTick、Stop、时钟恢复和外设唤醒顺序。这样的“深模块”不是为了文件多，而是为了让主业务不依赖具体低功耗顺序。

## 13. 增量设计：OLED从周期常显改为按需查看

> 本节为2026-09-03新增设计说明，不覆盖前文历史方案，不表示功能已经实现。当前进度和验收状态统一见[项目接续记忆](../记忆与产物/00-项目接续记忆.md)。用户确认OLED为3.3V插接模块；主控型号、共用I²C和CH1116命令以唯一源码及手册核对。

### 13.1 交互与运行策略

OLED作为现场调试/维护界面，不作为周期采集必需环节。建议上电默认关闭，普通瞬时按键经GPIO EXTI唤醒STM32，消抖后显示最近有效数据及更新时间；例如30秒无操作自动关闭，再按可延长查看或主动关闭。30秒是可调整的人机交互建议，不是已测参数。按键只发送请求，既不直接承载OLED供电，也不应在ISR内初始化屏幕、执行长延时或传输整帧。

RTC定时采集与按键查看必须分开：按键唤醒不必每次额外发一包LoRa，更不能不断将下一次采样重新推迟。Stop中SysTick已暂停，跨Stop的显示截止时间应使用RTC绝对时间；RTC Alarm可选择下一次采样或熄屏期限中较早的一项。画面静止时OLED能自行保持显示，MCU可再次Stop，不需要为等待熄屏持续忙循环。以上需未来改造现有统一采集循环及休眠入口，不能只接按键就视为完成。

### 13.2 先比较软关屏与硬断电

- **最小改动：** 保留OLED供电，只在需要时发Display ON，平时发CH1116 Display OFF并停止刷新。手册第33页说明`0xAE`停止振荡器、DC-DC和OLED驱动且保留显示RAM；`0xAF`恢复显示。它不是“只显示黑色画面”，但模块级残余电流仍要测量。
- **硬断电：** 在模块VCC前增加高边负载开关，关断时同时隔离OLED信号支路。可以去掉更多板级静态耗电，但增加元件、上电延迟、重新初始化和信号时序风险。是否值得由软关屏残余电流与新增器件漏电/重新上电能量共同判断。
- **源码提醒：** `OLED_Init()`采用CH1116的`0xAD/0x8B`，旧`OLED_DisPlay_On/Off()`却含`0x8D/0x14/0x10`，不能直接套用为已验证方案。Display OFF命令与切电源是两种独立动作。

### 13.4 共享I²C才是本次改造的关键

```text
常供电3.3V ── 高边负载开关 ── OLED模块VCC
                  ↑ GPIO电源使能
MCU PB6/PB7 ──┬──────────── AHT20（保留供电）
              └─ 双通道信号开关 ── OLED SCL/SDA
                       ↑ GPIO信号使能
GND共地；信号开关自身由常供电3.3V供电
```

MCU改成高阻不会删除板上的上拉电阻。AHT20一侧仍需高电平通信时，未隔离的OLED可能经SCL/SDA保护结构被反向供电，或其上拉电阻连接到已断电VCC而拖低公共总线。因而第6节“改高阻/切上拉”的简述只适用于整个相关总线域均被妥善处理的情况，不适用于只断开共享总线上的一只OLED。

主干上拉应留在常供电域，不能只依赖被切断的OLED板载上拉；OLED支路原有上拉通常随OLED电源域切换，具体需看模块板。双开关导通后两侧上拉并联，最终阻值、灌电流和上升沿必须复核。这里需要的是信号路径断开，不是用于高压安全的隔离器，也不是普通电平转换板。

关屏顺序：停止OLED刷新并结束I²C事务→Display OFF/按模块手册等待内部泵和高压域收尾→断开OLED两根信号→关闭OLED模块电源。开屏顺序：先接通电源→按模块手册等待供电和复位稳定→总线空闲时接通信号→重新初始化→清屏并重画最近有效数据。断电不保证OLED内部RAM保留；STM32自身Stop保留的RAM不等于OLED也保留。

### 13.5 验证思路

先确认转接板排针顺序，避免GND/VCC反接；模块内VPP高压由其自身电路管理，不从3.3V直接外接高压。比较正常显示、Display OFF、门控断电三种电流；开关自身、指示灯、板载稳压器均计入。检查屏幕关闭时AHT20仍可正常通信、OLED电源无明显反向抬升、反复上下电显示正常、按键无重入/抖动且RTC采样期限未被推迟。万用表可以初步测稳态电流，但量程负担压降和分辨率会影响结果；电源电压接近0也不能单独证明漏电为0。

## 14. 增量设计：雨滴模块只在采样窗口供电

雨滴板可以采用高边负载开关或适配电压的P-MOS控制VCC，GND始终共地，GPIO仅控制EN/栅极。若实际模块支持3.3V，可用3.3V→负载开关→雨滴模块VCC，AO仍接PB1/ADC1_IN9；模块若是5V供电，必须另核对AO最大电压并设计ADC保护/分压，不能因OLED接3.3V就推断雨滴板也相同。器件可沿用第13节的[TPS22919候选](https://www.ti.com/product/TPS22919)，在模块实际电压、电流范围内选型。

推荐采样顺序：RTC唤醒→恢复时钟→雨滴模块上电→等待供电及AO稳定→软件启动ADC并取8次平均→检查结果/保存→停止ADC→雨滴模块断电→继续本轮上报与休眠。上电等待取决于板载滤波、比较器/缓冲及电源上升过程，应通过实际AO稳定曲线或不同等待时间的采样比较确定，不能凭空指定固定毫秒值。8次平均不能替代上电稳定等待。

与OLED不同，PB1是独立的模拟输入，不是需要保持活动的共享I²C总线。如果只接AO、PB1保持模拟输入/无上下拉且不存在其他常电连接，通常不必再加OLED式的双路信号开关；但仍须核对AO/DO的板载电路。不要把PB1配置为高电平输出或上拉，DO未使用时可不接；若DO连接有常电上拉，需单独评估倒灌。通用机理参考[TI反向供电与断电隔离](https://www.ti.com/document-viewer/lit/html/SCDA015)，并非断言当前雨滴板已经测得倒灌。

OLED与雨滴模块建议使用独立开关/EN：OLED因用户查看而上电，雨滴因周期采样而短时上电。两者绑在同一个供电域会导致查看屏幕时雨滴板无谓耗电，或采样时OLED无谓上电。

两个软件边界：①断电的AO无有效干湿含义，即使ADC正常返回HAL_OK也可能读到低值，按当前映射被误判为100%湿润；必须只在上电稳定后采样并维护有效标志。②模块断电时DO不能作为可靠的降雨即时唤醒源，周期供电意味着只能在采样窗口检测，需接受检测延迟和短暂事件漏检风险；如必须实时触发，就要换常供电低功耗检测方案。

现有Rain_Read()没有上述电源控制，只做ADC启停与8次平均；具体实施状态见[唯一接续记忆](../记忆与产物/00-项目接续记忆.md)。这里的百分比是板面相对湿润程度，不是经过计量标定的毫米降雨量。验证时比较常供电与短时供电的干/湿ADC、电流和稳定时间，不只看模块LED是否熄灭。

## 15. 2026-09-17：15分钟节点运行、失败值及电池侧续航预算

本节新增并优先于前文旧建议，不删除历史设计。源码仍为sensor_project/sensor.design，不采用学习目录的快照。

### 15.1 两条触发路径

1. 上电首次采集；其后RTC绝对期限每900秒采集并上报。周期基准不随处理耗时或按键重置；错过期限跳到下一未来期限，不进行历史补发风暴。
2. 关屏按键→EXTI仅置位→主循环20ms消抖→采集AHT20/BH1750/雨滴→雨滴断电、BH1750关测量、AHT20自然待机→OLED上电/接总线/初始化/显示→约10秒后隔离并断电。再次按键可提前关屏。
3. 手动采集不增加无线发送；与周期同时到期合并采集并执行正常上报。亮屏期间到达采样期限，正常采集上报并更新有效显示，不重置原关屏期限。静态显示时MCU可以Stop，不需忙等10秒。
4. RTC计数为1Hz，名义10秒窗口存在不足1秒量化误差，收尾还有执行延迟；不能宣称精确10.000秒。OLED时限与采样时限取较早值编程同一个Alarm，不开第二个冲突RTC。
5. BH1750使用0x20单次高分辨率，等待180ms后读取，最后显式0x00；老连续模式API保留供历史调用。雨滴采8次后关闭PB14；AHT20不测量时待机，不把它说成断电。

### 15.2 失败与业务异常分开

AHT20已有发送/接收、Busy和量程检查；雨滴检查ADC返回和标定dry>wet、平均次数非零；BH1750检查软件I²C返回及关测量命令。失败不再发送旧值冒充本次读数。LoRa保留18字节v1、有效位与CRC：当前已提交`main.c`在AHT20失败时设`temp=-50.0f`，故温度空口原始值为`-500`（单位0.1℃；旧资料的`-10`已过时），无效湿度/光照0xFFFF，无效雨滴0xFF，对应valid位清零。网关JSON/故障CSV据valid位把无效字段统一输出-1，JSON另给sensor_errors；正常与仅越阈值数据只在终端打印，不写故障CSV。温度真实-1℃的valid仍为1，不能只看数值判断故障。有效但超过环境阈值的值保持原值并置ALERT；当前PC网关尚无单独的越阈值告警日志或推送。OLED失败字段显示ERR，BLE文本同样输出-1。

CRC正确的故障帧仍应ACK：ACK代表收到该帧，不代表传感器健康。断线模拟量不一定能靠ADC的HAL_OK识别，雨滴0/4095也可能是合法端点，不能无条件认作故障；若要检测探头断开需硬件诊断/标定。现有AHT20六字节版本没有新增CRC检验，不能声称识别全部传感故障。

### 15.3 GPIO与跨电源域

用户报告实测发现未用GPIO导致待机电流上升，设模拟输入后得到改善；未提供优化前读数，不编造节省比例。浮空数字输入在阈值附近扰动会增加输入缓冲/翻转电流，模拟模式可关闭数字输入路径，但不移除外部上拉、保护结构和器件漏电。

2026-09-23源码精简后，仅处理PA2/3/4/5/6/12、PB2/9/15，在初始化时设模拟输入；Stop保持GPIO配置，不再每轮保存和还原GPIOA/B的CRL/CRH；入睡前仍关状态灯。保留RTC晶振、SWD/JTAG、PC13 EXTI、UART/I²C、所有电源/模式输出，PA0/PB8保留作未来接线。硬件若占用了清单中的引脚，先修改清单，不能直接烧录照搬。LoRa实际PA8/PA9/PA1不擅自改成此前计划PA0/PA1/PB8。

关OLED先停止通信、Display OFF、隔离SCL/SDA，再切VCC；雨滴AO保持模拟无上拉。按键和电源EN不得一起改成模拟模式，否则可能丢唤醒或开关悬空。Stop前保留中断临界区重新检查按键事件与RTC期限，避免事件恰在WFI前到达却又睡过去；唤醒恢复时钟后继续业务。硬件隔离仍需实测，GPIO设置不保证漏电为零。

### 15.4 电量积分（全部是电池输出侧）
