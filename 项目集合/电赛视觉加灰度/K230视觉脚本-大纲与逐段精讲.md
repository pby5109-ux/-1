## 三、逐段精讲

### 3.1 硬件初始化（12–22 行）

```python
fpioa.set_function(11, fpioa.UART2_TXD)
fpioa.set_function(12, fpioa.UART2_RXD)
fpioa.set_function(32, FPIOA.GPIO32)
RECALIBRATE_KEY = Pin(32, Pin.IN, Pin.PULL_DOWN)
uart = UART(UART.UART2, baudrate=115200, bits=UART.EIGHTBITS, parity=UART.PARITY_NONE, stop=UART.STOPBITS_ONE)
```

- **FPIOA = 引脚功能选择**（K230 叫 FPIOA，STM32 叫复用/Remap）。芯片功能多、管脚少，一个 pad 同一时刻只能是一个功能，必须显式声明。
- 官方《GPIO和FPIOA》第 3 页写明：`UART2_TXD = BANK0_GPIO11`、`UART2_RXD = BANK0_GPIO12`，与代码一致。
- **FPIOA 编号 ≠ 排针物理脚号**。这里 11/12/32 是 SoC 的 IO 编号；具体接到哪个排针/接口，以实际接线为准（原理图第 6、7 页有 pad↔信号对应）。
- `Pin.PULL_DOWN` + 按键接 3.3V → 平时读 0，按下读 1，即“**高有效**”。（2026-09-17 修正：原写成 `PULL_UP` 低有效，与实际接线不符，硬件是按下接 3.3V、未按需要下拉。）
- UART2 是 K230 用户可用的两个串口之一（串口 0 被大核调试占用，串口 3 情况随固件不同）。

### 3.2 可调参数区（24–40 行）

| 参数 | 值 | 作用 | 调大 / 调小 |
|---|---|---|---|
| `DETECT_WIDTH/HEIGHT` | 480×320 | 检测分辨率，同时也是偏差基准（中心 240,160） | 改这里等于改协议坐标基准，别乱动 |
| `S_THRESHOLD` | 2000 | **候选最小外接框面积**（像素²），几何门限 | 调大 = 只认更近/更大的框 |
| `canny_thresh1/2` | 50 / 150 | 库内 Canny 双阈值（滞后阈值） | 调大 = 边缘更少更干净，太小会引入噪边 |
| `approx_epsilon` | 0.04 | 多边形拟合容差（占周长比例） | 调大 = 更容易拟成四边形，但形状失真 |
| `area_min_ratio` | 0.001 | 库内最小面积占全图比例（≈154 px²） | 调大 = 丢掉小矩形 |
| `max_angle_cos` | 0.5 | 库内四角余弦上限（|cos|≤0.5 即 60°–120°） | 调小 = 更严格接近直角 |
| `gaussian_blur_size` | 5 | 库内高斯核（奇数） | 调大 = 更平滑、更慢 |
| `length_threshold` | 120 | 对边长度差上限（像素） | 调小 = 更严格“对边等长” |

注意：`S_THRESHOLD`（面积，几何）和 Otsu 灰度阈值（分割）是**两个完全不同**的量，头部注释已专门提醒。

### 3.3 两个状态封装类

**`DebouncedPress`（43–57）** —— 机械按键按下/松开瞬间电平会抖几毫秒，直接读会误判多次。

```
raw     : 最近一次读到的原始电平
stable  : 已确认的稳定电平
changed : raw 上次变化的时刻
update(): raw 变化就记时刻；raw 与 stable 不同且持续 ≥30ms → 承认 stable=raw，并返回 raw==0
```

三个行为点：
1. **30ms 稳定才承认**（消抖）；
2. 返回值为真只在“稳定到高电平（按下）”那一次 → **长按只产生一次事件**，必须松开再按；
3. 初始化时 `stable = 当前电平`，所以**上电时按键已被按住不会误触发**；计时用 `time.ticks_diff`，能处理计数器回绕。

**`AutoThreshold`（60–87）** —— 三个字段构成一个小状态机：`value`（当前阈值）、`pending`（是否有重估请求）、`generation`（成功估计次数，可观测）。

- 启动 `pending=True` → 第一帧就估计；
- 估计成功后 `pending=False`，**阈值在两次估计之间保持不变**（不逐帧抖动）；
- `stats.max() <= stats.min()`（全黑/全白、无灰度对比）→ 返回 `None` 并**保留 pending**，下一帧重试，**不用旧值冒充本次结果**；
- 阈值越界（不在 0–255）直接 `ValueError`，宁可停下也不带病运行。

### 3.4 预处理链 `prepare_detection`（90–96）—— 本版最大的新增

```python
gray = raw.to_grayscale()          # 1) 转灰度
value = control.get(gray)          # 2) Otsu：直方图 → 阈值
gray.binary([(0, value)])          # 3) 按阈值二值化
return gray.binary(...).to_rgb888()# 4) 转回 RGB888 交给 cv_lite
```

**Otsu 是什么**：把 0–255 的灰度直方图切成两类，选让“类间方差最大（等价类内方差最小）”的那个分割点。它不需要人给参数，是“无屏自动阈值”的关键；`get_histogram().get_threshold().value()` 就是官方封装（文档明确写 “Uses the Otsu method”）。

**为什么要先二值化再交给 cv_lite**：cv_lite 内部是走边缘（Canny）的。二值化把“随光照变化的灰度问题”变成“固定的黑白问题”，边缘位置更稳定、更干净，等于用一次全局分割换来抗光照变化。

**二值化的极性**：`binary([(0,value)])` 把 [0,value] 的暗像素置白。黑框变白、白纸变黑。对 Canny 而言取反对边缘位置基本无影响，所以这里取哪个方向不关键，关键是阈值要能把靶框和背景分开。

**为什么又转回 RGB888**：cv_lite 的 `rgb888_*` 接口要求 RGB888 缓冲（文档：“请保证 Sensor 配置的出图为 RGB888 图，否则会报错”）。库里也有灰度入口，但保留比赛时验证过的调用路径，改动面最小。

**内存语义（重要）**：按 CanMV 文档，`to_grayscale()` 与 `to_rgb888()` **总是返回新图像对象**，`binary()` 默认原地修改；`to_numpy_ref()` 返回的是**与原图共享内存**的 numpy 引用，不是拷贝。所以：
- 每帧新增两次图像分配（灰度 + RGB888），这是本版新增的开销，长时间稳定性与帧率需上板实测；
- 注释“detection 存活到库调用结束”就是这个原因——对象被回收，库手里的指针就悬空了。

### 3.5 cv_lite 矩形检测（198–201 行）

```python
rects = cv_lite.rgb888_find_rectangles_with_corners(
    image_shape, pixels, canny_thresh1, canny_thresh2,
    approx_epsilon, area_min_ratio, max_angle_cos, gaussian_blur_size)
```

- `image_shape` 顺序是 **[高, 宽]**（官方文档示例 `[480,640]`），这里 `[320, 480]`；
- `pixels` 必须是 `ulab.numpy.ndarray` 引用（`to_numpy_ref()` 给的正是）；
- **返回值**：列表，每个矩形 12 个数 —— `[x, y, w, h, x0,y0, x1,y1, x2,y2, x3,y3]`（外接框 + 4 个角点，角点按边顺序环绕，脚本的连线/对边配对依赖这个顺序）。

库内部流水线（**按参数推断，未核验源码**）：高斯模糊 → Canny(50/150) → 轮廓多边形拟合(0.04) → 四角余弦判据(≤0.5，即角在 60°–120°) → 面积过滤(≥0.001×图面积)。它只保证“像个矩形”，**不保证是靶标**——所以才需要下一段。

### 3.6 几何筛选 `select_rectangle_center`（168–191）

按外接框面积**从大到小**逐个验证，第一个全通过的就返回中心：

1. 结构完整：`len(r) >= 12` 且 `w>0, h>0`；
2. 面积 `w*h > S_THRESHOLD(2000)`；
3. 四条边最短 > 30 px；
4. 对边长度差 < 120：上↔下、左↔右各一对；
5. 上/下平行、左/右平行、上⊥左（`are_segments_parallel` / `are_segments_vertical`，容差 30°）；
6. `find_intersection` 求两条对角线交点，**必须存在且落在画面内**。

设计意图与面试价值：
- 第 3–5 条把“太小的、拉长的、梯形的、歪斜超过约 30° 的”全部拒掉，靶纸上的黑框恰好满足；
- **按面积排序逐个回退**是本版相对比赛版的改进：比赛版只取最大框，最大框若因干扰（黑线、反光、背景方形物）被拒，当帧就整帧放弃；
- 边界检查不是可有可无：它同时保证了 `send_center` 里 |dx|≤240、|dy|≤160，**报文才凑得满 4+4 字符**。

### 3.7 中心解算 `find_intersection`（133–161）

用两条对角线（c0–c2 与 c1–c3）求交点，叉积/行列式解法：

```
t = cross(AC, CD) / cross(AB, CD)   # 沿第一条线的参数
交点 = P1 + t * AB                   # det==0（平行）→ 返回 None
```

- 几何含义：仿射投影下，四边形对角线交点 = 中心；**强透视下它不等于真正的投影中心**（那要用单应矩阵），这是方法的适用边界；
- 相比“四角取平均”（教程版做法），交点法自带退化自检：对角线平行时返回 `None`，脚本据此直接判废；
- 公式中 `u` 算了但没用，属于冗余但无害的计算。

### 3.8 报文与接收端（206–214）

```python
dx = DETECT_WIDTH//2 - center[0]     # 240 - cx
dy = DETECT_HEIGHT//2 - center[1]    # 160 - cy
uart.write('[' + f"{dx:+04d}" + f"{dy:+04d}" + '*]')   # 例：[+012-034*]
```

- **语义**：画面中心 − 目标中心。`dx>0` → 靶在画面中心**左侧**；`dy>0` → 靶在中心**上方**；
- `f"{v:+04d}"`：强制带符号 + 至少 3 位补零 → 恒为 4 字符。配合 3.6 的边界检查，载荷恒为 8 字符，整包 11 字节；
- **定长是为了接收端好写**：云台 `Uart.c` 的 ISR 状态机是 `'[' → 收字节到 '*' → 等 ']' → 置 Serial_RxFlag`，`work.c` 再检查 `strlen==8`，前 4 字符 `atoi` 给 `x_site`、后 4 字符给 `y_site`。接收端不做任何字符串解析，全靠固定偏移；
- 失败分支发 `(x=999,y=999)`（不含 `[`）→ 云台状态机完全不认，**会继续用上一次的坐标**。所以：不能宣称“目标丢失保护已完成”，改 `[+999+999*]` 更不行（会被当成真实误差）。

### 3.9 生命周期与主循环（217–268）

- `camera_init`：`Sensor()` → `reset()` → `set_framesize(480,320)` → `set_pixformat(RGB888)` → `MediaManager.init()` → `run()`（媒体管理器必须在 run 前初始化）；
- `capture_picture` 每帧：`os.exitpoint()`（IDE 停止按钮靠它生效）→ 按键事件 → `request()` → `snapshot()` → `process_frame()` → `send_center()` → `del raw`；
- `camera_deinit` 用 `try/finally` 保证 `sensor.stop()` 一定执行，再 `MediaManager.deinit()`；`main` 的 `finally` 保证异常/中断时也释放。

## 五、已知风险与上板核查清单

1. **失败报文不兼容控制端**：云台收不到 `[` 开头的包就一直用旧坐标，没有超时/有效位机制。若要闭环安全，需先设计“目标有效位/超时策略”。
2. **每帧两次图像分配**（灰度、RGB888）是本版新增开销，摄像头在线时内存/帧率需实测（列表里已列“长时间内存稳定性”）。
3. `stats.max()/min()`、`get_threshold()` 在官方文档中有定义，但在本块板子/固件上尚未实跑，需上板确认。
4. **Otsu 是全局阈值**：不理解“谁是靶标”，背景占比大、反光、阴影都会影响；启动/按键重估时应让目标占据合适比例的画面。
5. 30° 容差意味着：靶纸在画面里旋转超过约 30° 会被几何门限拒掉（斜看影响不大，平面内旋转影响大）。
6. 与教程模板相比，`camera_deinit` 少了 `os.exitpoint(EXITPOINT_ENABLE_SLEEP)` + `time.sleep_ms(100)` 再 deinit 的步骤；若上板出现释放异常，可对照教程补回。
7. **死代码**（不影响运行，可清理）：`split_to_2d`、`get_vertices`、`find_max`、模块级 `last`、注释掉的 2D 版 `are_segments_vertical`、未使用的 `gc/sys/atan/atan2` 导入。

## 六、面试预演 5 问（附要点）

1. **为什么先 Otsu 二值化，再让 cv_lite 做 Canny？** —— 用一次全局分割把光照相关灰度问题变成固定黑白问题，边缘位置稳定、抗光照变化；代价是全局阈值对背景占比和反光敏感。
2. **为什么按面积排序逐个验证，而不是只取最大框？** —— 最大框可能是背景干扰（黑线、方形干扰物），旧版最大框被拒就整帧放弃；逐个回退提高有效帧比例，代价是多几次几何计算（可忽略）。
3. **为什么用对角线交点定位？** —— 仿射近似下即四边形中心，且自带退化自检（平行→None）；强透视下会偏离真实投影中心，这是方法边界。
4. **报文为什么定长，失败怎么处理？** —— 接收端 ISR 按固定偏移切片，8 字符 + `[ * ]` 是最省的协议；失败发不含 `[` 的消息，接收端直接忽略（已知缺陷：没有超时保护）。
5. **阈值为什么不逐帧更新？** —— 逐帧 Otsu 会随画面内容抖动（背景物进画面阈值就变），按需重估+帧间保持让检测参数稳定；无对比帧不估计并重试，避免用失效旧值。
