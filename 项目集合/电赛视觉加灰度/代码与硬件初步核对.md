## 四条主线

| 模块 | 源码事实 |
|---|---|
| 五路灰度 | PB24、PB20、PA27、PB19、PB18数字输入，拼为bit4～bit0；OLED直接显示0/1，Track_err另作偏差映射；不是K230灰度图或ADC连续灰度值 |
| 小车OLED | PA24=SCL、PA23=SDA，软件I²C；头文件注明SSD1306，OLED_GRAM[144][8]缓存，OLED_Update调用刷新；驱动有外部作者/借鉴声明，负责显示不等同全部底层原创 |
| 小车按键 | 逻辑键1～4对应PA18、PA14、PA13、PA4，低有效；按住单次触发，全松开5次扫描后复位；无固定扫描周期，不能称5ms消抖 |
| K230 | CanMV Python，RGB888 480×320采集，ST7701显示配置800×480；GPIO11/12复用UART2，115200、8N1；GPIO32/33上拉输入调面积阈值 |
| 云台显示/按键 | OLED为I2C0、400kHz、PA31=SCL、PA28=SDA；显示x_site/y_site、输出及状态；按键20ms延时→等待松手→20ms延时，会阻塞主循环 |

小车键1切六页、键2切任务、键3在任务1增加N、键4在页面1切启动状态，否则任务1时减少N；N是uint8_t且没有边界保护。显示页面覆盖主状态、姿态、灰度、轮速/里程、坐标和PID参数，相关控制仅作为数据来源。

视觉链：snapshot→RGB888数组引用→cv_lite矩形检测→选外接框面积最大候选→面积/边长/对边差/平行垂直筛选→对角线交点→(240-cx,160-cy)→UART。

库参数为Canny 50/150、拟合比例0.04、面积比例0.001、角余弦0.5、高斯核5；未核验库内部。二次筛选四边大于30、对边差小于120、角度容差30度。面积阈值默认2000，步长500、范围500～10000；两键共享200ms时间门限，长按可重复调整。

成功帧如[+012-034*]，总11字节，两段偏差各4字符；星号是定界符而非校验和。云台Uart.c组帧，work.c的uart_work要求8字符载荷并拆成x_site/y_site。检测中心(240,160)不能替换成800×480屏幕中心。

## 源码发现

1. 灰度页e_hd、hd_pid实际显示servo_x、servo_y，不能照标签讲为灰度误差/PID输出。
2. K230失败分支发(x=999,y=999)，云台只识别[...*]，失败消息不能通过成功帧路径更新坐标。是否另有超时保护未审阅，不能断言整机实际行为。
3. Track_err在24、28、7、3四种状态未给局部error赋值就返回；error_flag混淆居中0与无检测0。已确认源码风险，未修复、未实测。
4. 最大候选失败后不尝试较小候选；交点None未防护，异常会退出采集循环。云台收包数组未见长度上限检查，异常尾部缺少完整复位路径。
5. 用户新确认K230视觉设计职责，不扩大为PID/电机等团队模块原创，不据文件夹名称判定赛场最终版本。

## 硬件证据与中间文件

本地硬件文档第11页GPIO段包含40针排针和GH1.25-4P串口/I²C接口；第13～14页CSI段说明CSI2为默认摄像头接口；第14～15页DSI段描述LCD、背光与触摸。K230 LCD与MCU OLED是不同显示硬件。

尚待核对摄像头/灰度/OLED实物型号、供电、GPIO11/12/32/33实际接线、两块MCU板分工与最终固件版本。FPIOA号不等于排针物理脚号，K230主板图不能证明小车接线。

中间文件/核对硬件页.py通过pypdfium2从原始原理图生成第7、14页PNG，可运行重建；PNG为可重建核对缓存，脚本保留作为来源。本轮图像查看工具因Windows沙箱权限故障失败，未完成原理图视觉逐线核验，不宣称实物确认。
