## 一、关键字、声明与预处理

<a id="q001"></a>

### 1. static 有哪些作用？为什么只初始化一次？

**简答**：在函数内修饰变量，使变量具有静态存储期，退出函数后仍保留值；在文件作用域修饰变量或函数，使其具有内部链接，限制在本翻译单元内使用。静态存储期变量在程序启动时初始化一次，未显式初始化时按类型初始化为零。

**补充**：“保留值”不等于值不能改变；局部 static 的作用域仍是所在代码块。

**来源**：精简 p.2–3；精华 p.1、4。

<a id="q002"></a>

### 2. extern 有什么作用？声明和定义有什么区别？

**简答**：声明告诉编译器名字和类型；定义提供变量实体或函数实现。`extern int g;` 通常是声明，用来引用其他位置定义的变量；`int g = 1;` 是定义。未声明通常在编译阶段报错，已声明但缺少所需定义通常在链接阶段报错。

**补充**：`extern int g = 1;` 带初始化，是定义；`int g;` 在文件作用域是暂定定义，不能简单当作 extern 声明。

**来源**：精华 p.4–5、20。

<a id="q003"></a>

### 3. const 的作用和使用场景是什么？

**简答**：const 用来表达只读约束，常用于只读配置、查表数组、函数输入参数以及返回的只读数据指针。`const int *p` 限制通过 p 修改所指对象；const 本身不保证对象放在 Flash，也不能替代同步。

**补充**：原题中的常引用、类成员和常对象部分暂不收录。

**来源**：精简 p.3–4；精华 p.7–9。

<a id="q004"></a>

### 4. 常量指针、指针常量、指向常量的常量指针怎么区分？

**简答**：直接看声明：`const int *p` 或 `int const *p`，p 可改变指向，不能通过 p 修改值；`int * const p`，p 不能改变指向，所指值可改；`const int * const p`，两者都受限制。

**补充**：口述时优先说“指向只读数据的指针”和“指针本身只读”，避免中文名称混淆。

**来源**：精简 p.13；精华 p.37。

<a id="q005"></a>

### 5. volatile 有什么作用？典型场景是什么？

**简答**：告诉编译器对象的值可能由正常代码之外的因素改变，要按实现规定保留可观察访问。典型场景是内存映射外设寄存器，以及中断修改、主循环读取的简单标志。volatile 不保证原子性、线程同步、内存顺序或 Cache 一致性。

**补充**：多任务共享数据应使用锁、原子操作或平台同步机制；中断标志还需满足平台的访问原子性要求。核对：[GCC volatile 说明](https://gcc.gnu.org/onlinedocs/gcc/Volatiles.html)。

**来源**：精简 p.2；精华 p.10–12。

<a id="q006"></a>

### 6. const 和 #define 有什么区别，怎么选择？

**简答**：`#define` 在预处理阶段替换记号，可定义常量、表达式和编译开关；const 定义有类型的只读对象，适合类型检查与接口表达。一般只读数据用 const，条件编译或宏展开用 define。

**补充**：按常见 C11/C17 规则，`const int n=10;` 通常不是整型常量表达式；枚举常量或宏更适合要求编译期常量的场合。不能笼统说 const 一定省内存。

**来源**：精简 p.15–16；精华 p.9。

<a id="q007"></a>

### 7. typedef 和 #define 有什么区别？

**简答**：typedef 给已有类型取别名，受 C 的作用域规则约束；define 做预处理替换，直到 undef 或当前预处理单元结束。类型别名优先用 typedef，避免文本替换产生声明歧义。

**补充**：`#define P int *` 后 `P a,b;` 只有 a 是指针；`typedef int *P;` 后 `P a,b;` 两者都是指针。`const P` 修饰 typedef 指针别名时，限定的是指针本身。

**来源**：精简 p.16–17。

<a id="q008"></a>

### 8. 宏中的 # 和 ## 有什么作用？

**简答**：`#` 把函数式宏参数字符串化；`##` 把两侧预处理记号拼接成一个合法记号，常用于生成标识符。参数直接参与 # 或 ## 时不会先按普通规则展开；需要先展开再处理时使用两层宏。

```c
#define STR_INNER(x) #x
#define STR(x) STR_INNER(x)
#define CAT_INNER(a, b) a##b
#define CAT(a, b) CAT_INNER(a, b)
```

**补充**：拼接结果必须是合法记号，不要求拼接出的名字已经声明。

**来源**：精简 p.1–2。

<a id="q009"></a>

### 9. #error 用来做什么？

**简答**：在预处理时产生诊断信息，用来拒绝不支持的平台、缺失的配置或互相冲突的编译选项，尽早暴露配置错误。

**补充**：常与 `#if`、`#ifdef` 配合；例如未定义板型时报告错误。

**来源**：精简 p.15。

<a id="q010"></a>

### 10. #include <...> 和 #include "..." 有什么区别？头文件的作用是什么？

**简答**：头文件集中声明接口、类型和宏，使多个源文件共享一致定义并接受编译检查。尖括号通常用于系统头，双引号通常先搜索当前文件相关目录再搜索配置路径；具体搜索规则由编译器决定。

**补充**：头文件应使用包含保护；包含头文件不会自动把库的实现链接进来。

**来源**：精简 p.17–18。

<a id="q011"></a>

### 11. 能不能在头文件定义 static 变量或普通全局变量？

**简答**：头文件定义 static 变量合法，但每个包含它的翻译单元会有独立副本，适合明确需要独立数据的情况，不适合共享状态。共享全局变量通常在头文件写 extern 声明，在一个 `.c` 文件提供定义。

**补充**：头文件直接定义普通全局变量容易引起重复定义；只有一个文件赋初值也不是通用解决办法。

**来源**：精简 p.18–19。

<a id="q012"></a>

### 12. 全局变量和局部变量有什么区别？能否同名？

**简答**：主要区别是作用域和存储期：全局变量通常具有静态存储期，自动局部变量随所在代码块的执行存在；局部 static 也具有静态存储期。内层局部变量可以与外层全局变量同名，并在该作用域内遮蔽它。

**补充**：自动局部变量未初始化时不能当作零使用；实际可能放栈或寄存器，不能一概说所有局部变量都在栈上。

**来源**：精简 p.19。

<a id="q013"></a>

### 13. 写一个返回较小值的 MIN 宏，要注意什么？

**简答**：给参数和整体表达式加括号，避免运算符优先级问题。宏可能重复求值，不能传入自增、自减或有副作用的表达式；需要单次求值时使用合适类型的 inline 函数。

```c
#define MIN(a, b) (((a) < (b)) ? (a) : (b))
```

**补充**：`MIN(i++, j++)` 会产生意料之外的多次修改；宏括号不能解决这个问题。

**来源**：精简 p.18；精华 p.19。

<a id="q014"></a>

### 14. 怎样用宏表示一年有多少秒？

**简答**：忽略闰年时是一年 365 天，每天 24 小时，每小时 60 分钟、每分钟 60 秒，结果为 31536000。乘法从足够宽的无符号类型开始，避免在窄 int 平台上先溢出。

```c
#define SECONDS_PER_YEAR (365UL * 24UL * 60UL * 60UL)
```

**补充**：不能只在最后一个因子加 UL 来保证所有前面的中间运算安全。

**来源**：精简 p.17。

<a id="q015"></a>

### 15. 如何用宏求数组元素个数？

**简答**：在真实数组所在作用域，用数组总字节数除以一个元素的字节数。传入指针或已退化为指针的函数形参时不成立，函数接口应显式传入长度。

```c
#define ARRAY_COUNT(a) (sizeof(a) / sizeof((a)[0]))
```

**补充**：数组参数写成 `int a[10]` 仍会调整为指针。

**来源**：精华 p.20。

<a id="q016"></a>

### 16. 不使用流程控制语句，如何打印 1～1000？

**简答**：按题目限制，可以用宏逐层重复展开十次，三层得到一千次输出。工程中通常直接用循环，宏展开会增加代码体积，不适合为了技巧牺牲可维护性。

```c
#define REPEAT10(s) s s s s s s s s s s
/* 在函数内： */
int n = 1;
REPEAT10(REPEAT10(REPEAT10(printf("%d\n", n++);)))
```

**补充**：以下代码是原题思路的 C 版本，每次 printf 都是独立语句。

**来源**：精简 p.18。

<a id="q017"></a>

### 17. 为什么通常少用 goto？完全不能用吗？

**简答**：随意跳转容易打乱控制流，优先用循环和条件语句。但 goto 在 C 中可以用于统一释放资源、集中处理错误，减少多层嵌套；只在同一函数内跳转，保持路径清楚。

**来源**：精华 p.21。

<a id="q018"></a>

### 18. 死循环有哪些写法？

**简答**：常见写法有 `while (1) {}`、`for (;;) {}` 和 `do {} while (1);`。MCU 主循环可持续处理事件；RTOS 任务循环通常需要阻塞或延时，避免一直占用 CPU。

**补充**：不要用无限递归代替循环，递归可能耗尽栈。

**来源**：精华 p.21–22。

## 二、表达式与 sizeof

<a id="q019"></a>

### 19. 左值和右值怎么理解？

**简答**：在 C 中，左值表达式用于标识一个对象；只有可修改左值才能作为普通赋值的左侧。右侧可以是对象读出的值或计算结果。const 对象也是左值，但不是可修改左值。

**补充**：`a`、`*p`、`arr[i]` 可标识对象；不能把“左值”简单定义为一定能修改的东西。

**来源**：精简 p.6。

<a id="q020"></a>

### 20. 什么是短路求值？

**简答**：`&&` 左侧为假时不计算右侧；`||` 左侧为真时不计算右侧。常用于先验证条件再访问数据，例如 `p != NULL && *p == 1`。

**补充**：右侧的自增或函数调用可能不执行；按位运算 `&`、`|` 不具备这个短路规则。

**来源**：精简 p.6。

<a id="q021"></a>

### 21. ++a 和 a++ 有什么区别？哪个效率高？

**简答**：前置自增先修改 a，再得到新值；后置自增得到旧值，并产生对 a 的增量修改。若表达式结果被丢弃，普通整数上二者通常可生成相同代码，不能断言前置永远更快。

**补充**：不要在没有明确求值顺序的同一表达式里对同一变量重复修改，例如 `f(i++, i++)` 在常见 C11/C17 下是未定义行为。

**来源**：精简 p.6–7。

<a id="q022"></a>

### 22. sizeof 和 strlen 的区别是什么？

**简答**：sizeof 是运算符，返回类型或对象的字节大小；strlen 是库函数，统计第一个 `\0` 之前的字符数。二者都返回 size_t。普通固定大小类型的 sizeof 通常编译期可确定，strlen 取决于字符串内容。

**补充**：`char s[]="abc";`：sizeof(s)=4，strlen(s)=3；sizeof 指针得到指针大小。可变长数组相关 sizeof 可能运行时求值。

**来源**：精简 p.4–5。

<a id="q023"></a>

### 23. strlen("\0") 和 sizeof("\0") 分别是多少？

**简答**：strlen 的结果是 0，因为第一个字符就是结束符；sizeof 的结果是 2，因为该字符串字面量包含显式 `\0` 和编译器追加的结束符。

**来源**：精简 p.4。

<a id="q024"></a>

### 24. 不用 sizeof 能否求 int 占几个字节？

**简答**：针对实际对象，面试常见思路是比较相邻 int 元素的字节地址间距。实际工程优先使用 sizeof；指针相减需要满足 C 的对象边界规则，不能拿任意地址相减。

```c
int a[2];
unsigned char *begin = (unsigned char *)&a;
unsigned char *next = (unsigned char *)(a + 1);
ptrdiff_t bytes = next - begin; /* 需要 <stddef.h> */
```

**补充**：严谨示例在同一数组对象的字节表示范围内计算。

**来源**：精简 p.5。

## 三、内存、生命周期与对齐

<a id="q025"></a>

### 25. C 语言常见的内存分配方式有哪些？

**简答**：工程上常见静态存储、自动存储和动态分配：全局/static 对象通常长期占用静态区域；普通局部对象由编译器管理，常用栈或寄存器；malloc 等从堆申请，需正确释放。

**补充**：这些是常见实现方式，C 标准的存储期分类与 MCU 链接段并非完全等同。

**来源**：精简 p.7；精华 p.22–24。

<a id="q026"></a>

### 26. .text、.rodata、.data、.bss、堆和栈分别放什么？

**简答**：典型 MCU 中，.text 放代码，.rodata 放只读数据；.data 放具有非零初值的全局/static 数据，启动时从 Flash 复制到 RAM；.bss 放零初始化或未显式初始化的全局/static 数据，启动时清零。堆供动态分配，栈供函数调用和自动对象。

**补充**：最终归段由工具链和链接脚本决定；const 不保证固定归段。.bss 占 RAM，但通常不在固件镜像中逐字节保存零。

**来源**：精简 p.188；精华 p.23–24、135。

<a id="q027"></a>

### 27. 堆和栈有什么区别？

**简答**：栈通常由编译器管理，按函数调用规则使用，分配回收开销较小，主要风险是空间不足和越界；堆由分配器管理，生命周期可跨函数，需管理释放，主要风险是分配失败、泄漏和碎片。

**补充**：MCU 中二者容量来自 RAM 与工程配置；生长方向、具体大小和管理结构都不是 C 语言固定规定。

**来源**：精简 p.7、188–189；精华 p.24–25。

<a id="q028"></a>

### 28. 栈在函数调用中起什么作用？什么是栈帧？

**简答**：栈用于保存调用现场、需要落栈的参数、局部数据及返回信息。栈帧是一次函数调用使用的栈空间，返回时恢复调用者状态。具体保存哪些内容由架构、ABI 和优化决定。

**补充**：部分参数、返回值和局部变量可放寄存器；优化后函数可能没有独立帧指针，不能把 x86 的 EBP/ESP 当作 MCU 通则。

**来源**：精简 p.7、21–22。

<a id="q029"></a>

### 29. C 函数参数一定从右向左压栈吗？求值顺序是什么？

**简答**：不是。传参位置和栈布局由 ABI 决定，参数可能先放寄存器；常见 Arm AAPCS32 基础调用约定使用 r0～r3 传递部分参数，其余按规则使用栈。实参表达式的求值顺序与压栈顺序是两回事，C 不保证普通函数实参按从左到右或从右到左求值。

**补充**：核对：[Arm AAPCS32](https://github.com/ARM-software/abi-aa/blob/main/aapcs32/aapcs32.rst)。

**来源**：精简 p.8。

<a id="q030"></a>

### 30. malloc/free 的基本使用规则和实现原理是什么？

**简答**：malloc 按字节申请一块连续可访问空间，内容未初始化，失败返回 NULL。free 释放有效分配块，分配器通常维护空闲块、管理信息，并可能拆分或合并块；具体算法因实现而异。

**补充**：只能释放分配接口返回的有效起始指针；不能释放局部数组、字符串字面量、块内部地址或重复释放。free(NULL) 不做操作；MCU 的 malloc 不必依赖操作系统系统调用。

**来源**：精简 p.7–9；精华 p.27。

<a id="q031"></a>

### 31. 局部可以定义 2048 个元素的大数组吗？

**简答**：可以，但要估算实际字节数和栈预算，例如 2048 个 4 字节 int 就需约 8 KB，还未计入其他调用开销。不能只看元素个数判定安全；栈不足时可考虑静态缓冲区、内存池或受控堆分配。

**补充**：全局/static 缓冲区会长期占 RAM，还要解决并发复用；转到堆上不代表没有内存成本。

**来源**：精华 p.25。

<a id="q032"></a>

### 32. malloc 能申请超过物理内存的空间吗？

**简答**：取决于平台。带虚拟内存的系统可能允许虚拟地址分配超过当前物理 RAM，但不保证实际访问都成功；典型无虚拟内存 MCU 受可用堆和最大连续空闲块限制。

**补充**：本笔记以 MCU 为主，不把桌面系统的虚拟内存机制当作裸机能力。

**来源**：精华 p.25。

<a id="q033"></a>

### 33. 什么是内存泄漏，怎样检测与避免？

**简答**：动态申请的内存已经不再需要，却未正确释放或丢失了释放它的指针。明确所有权、统一清理失败路径、防止指针被覆盖；可记录分配/释放和未释放块，长期压测观察堆变化。

**补充**：只统计申请次数减释放次数可能漏掉大小不一致等问题；结构体内独立申请的成员需要按所有权逐级释放。主机可配合内存检查工具。

**来源**：精简 p.9；精华 p.31–32。

<a id="q034"></a>

### 34. 野指针、悬空指针和空指针有什么区别，如何避免？

**简答**：空指针表示不指向有效对象；野指针常指未初始化或指向无效地址的指针；悬空指针指向生命周期已结束或已释放的对象。指针初始化、检查分配结果、保证对象存活、避免越界，释放后按所有权清理引用。

**补充**：把一个指针置 NULL 不会自动清除其别名；具有静态存储期的未显式初始化指针按语言规则初始化为空指针，不能说所有未初始化指针都是随机值。

**来源**：精简 p.14；精华 p.43–44。

<a id="q035"></a>

### 35. 结构体为什么要对齐，怎样计算和设置？

**简答**：对齐使成员满足处理器/ABI 的访问要求，避免部分平台的异常，并可能提高访问效率。计算时按成员顺序把偏移补到成员所需边界，再给结构体尾部补齐，使数组中的每个元素也满足对齐。

**补充**：常见 int 为 4 字节且按 4 字节对齐时，`char,int,char` 通常占 12 字节。可调整成员顺序减少填充；支持时用 pack 限制对齐、C11 _Alignas 提高对象对齐。打包可能导致非对齐访问，通信格式宜显式序列化。

**来源**：精简 p.5–6；精华 p.33–35。

<a id="q036"></a>

### 36. struct 和 union 有什么区别？联合体大小怎么计算？

**简答**：struct 的成员分别占空间，可以同时保存各成员；union 的成员共享空间，写一个成员会改变其他成员看到的表示。struct 大小要计成员间和末尾填充；union 大小至少容纳最大成员，并满足整体对齐。

**补充**：不能只取“最大成员字节数”而忽略对齐；例如最大成员 20 字节、整体要求 8 字节对齐时，大小可能补到 24 字节。

**来源**：精简 p.5–6；精华 p.34–35。

<a id="q037"></a>

### 37. 什么是位域？大小和位顺序固定吗？

**简答**：位域用 `成员名:位数` 声明，把若干标志组织为指定位宽。位域的分配顺序、跨单元规则、对齐以及部分可用基础类型受实现影响，不能只把位数相加就断言结构体大小。

**补充**：不能对位域成员直接取地址，也不能仅由大小端推断位域布局；协议和寄存器操作通常用明确的掩码、移位，或芯片提供的定义。

**来源**：精简 p.142；精华 p.33–34。

<a id="pointers"></a>

## 四、指针与数组

<a id="q038"></a>

### 38. 数组名和指针有什么区别？

**简答**：数组是连续存储同类型元素的对象，指针是保存地址的对象。数组表达式在多数场合转换为首元素指针，但数组本身不是指针；sizeof 数组得到整个数组大小，sizeof 指针得到指针大小。

**补充**：数组名不能像指针变量那样赋值或自增，但 `a+1` 等表达式合法；常见不退化情形包括 sizeof 和 `&a`。

**来源**：精简 p.12；精华 p.37。

<a id="q039"></a>

### 39. a 和 &a 有什么区别？a+1 与 &a+1 一样吗？

**简答**：对 `int a[10]`，a 在普通表达式中转换为 int*，加 1 跨一个 int；`&a` 是指向整个数组的指针，类型为 `int (*)[10]`，加 1 跨整个数组。起始地址对应同一位置，类型和步长不同。

**来源**：精简 p.12；精华 p.37。

<a id="q040"></a>

### 40. 数组指针和指针数组如何区分？

**简答**：`int (*p)[4]` 是一个指针，指向含 4 个 int 的数组；`int *p[4]` 是含 4 个 int* 元素的数组。前者常用于连续二维数组的行访问，后者可存放多个独立地址。

**补充**：二维数组 `int a[3][4]` 可用于初始化 `int (*p)[4]=a`；不能直接当成 int**。

**来源**：精简 p.9–12；精华 p.38。

<a id="q041"></a>

### 41. 二级指针有什么用途？二维数组能用 int** 接收吗？

**简答**：二级指针保存另一个指针对象的地址，常用于在函数内修改调用方指针，或管理指针数组/链表头。连续二维数组退化为行指针，不是 int**；若每行单独分配、外层存行地址，才可能采用二级指针布局。

**补充**：资料的 `int (*p)[3]` 是数组指针，不是指针的指针，已纠正。

**来源**：精华 p.35–36。

<a id="q042"></a>

### 42. 指针占多少字节？所有指针都一样大吗？

**简答**：大小由目标平台、ABI 和指针类型决定，普通对象指针在常见 32 位 MCU 上通常为 4 字节，常见 64 位平台通常为 8 字节。实际用 sizeof 对具体类型确认。

**补充**：不能仅由宿主电脑位数判断目标固件指针大小；C 也不保证函数指针与所有对象指针都一样大。

**来源**：精华 p.47。

<a id="q043"></a>

### 43. 函数指针和指针函数有什么区别？用途是什么？

**简答**：函数指针是指向函数的指针，例如 `int (*fp)(int,int)`，可用于回调、状态机和操作表；指针函数是返回指针的函数，例如 `int *f(int,int)`。关键区别是 fp 本身是指针，f 本身是函数。

**补充**：调用函数指针时签名必须匹配；返回的指针应指向仍然有效的对象，不能返回自动局部对象的地址。函数指针不能做标准 C 的加减运算。

**来源**：精简 p.10–12；精华 p.39–41。

<a id="q044"></a>

### 44. C 中传值和传指针有什么区别？如何修改调用方的指针？

**简答**：C 函数参数都是按值传递，指针参数复制的是地址值。修改普通形参不改变调用方变量，解引用有效指针可修改调用方对象；要改变调用方指针本身，传二级指针或返回新指针。

**补充**：`void f(int *p){p=...;}` 只改局部副本；`void f(int **p){*p=...;}` 可改调用方指针。引用传参属于 C++，暂不收录。

**来源**：精华 p.43。

<a id="q045"></a>

### 45. 指针转换后再加偏移，结果有什么区别？

**简答**：`p+n` 按所指类型的大小移动 n 个元素；转为 unsigned char* 后加 n，按字节移动；若平台支持，转为 uintptr_t 后加 n 是整数运算。类型转换不自动保证目标地址可访问。

**补充**：指针运算要满足对象/数组边界；不能在任意固定地址上用标准数组规则保证安全。unsigned long 不保证能容纳所有平台的指针。

**来源**：精简 p.12。

<a id="q046"></a>

### 46. 二维数组的 *(a[1]+1)、*(&a[1][1])、(*(a+1))[1] 是什么？

**简答**：在有足够行列的二维数组中，这三种表达式都访问 `a[1][1]`。先确认 a 的行指针类型，再按括号和运算符优先级逐层展开。

**补充**：`a+1` 到第二行，`*(a+1)` 是该行，后面的 `[1]` 取该行第二个元素。

**来源**：精简 p.23。

<a id="q047"></a>

### 47. 数组下标可以是负数吗？

**简答**：可以对指向数组中间的指针使用负下标，前提是结果仍在同一数组的有效范围。例如 `int *p=&a[4];`，a 至少有 5 个元素时，`p[-1]` 等于 a[3]。

**补充**：对数组首地址使用 a[-1] 越界；编译通过不代表访问合法。

**来源**：精简 p.23–24。

## 五、位操作、字节序与寄存器

<a id="q048"></a>

### 48. 怎样设置、清除和翻转某一位，保持其他位不变？

**简答**：构造无符号掩码：置位用或，清位用与掩码取反，翻转用异或。位序从 0 开始，移位数必须小于类型位宽。

```c
uint32_t mask = UINT32_C(1) << 3;
a |= mask;   /* 置 1 */
a &= ~mask;  /* 清 0 */
a ^= mask;   /* 翻转 */
```

**补充**：以下以 uint32_t、bit 3 为例，需要 <stdint.h>。

**来源**：精简 p.26；精华 p.21。

<a id="q049"></a>

### 49. 如何安全翻转多任务共享寄存器的某一位？

**简答**：先确认寄存器允许读改写，位序和访问宽度正确；优先使用硬件原子置位/清位机制。否则使用平台适合的短临界区，避免任务或中断在读与写之间修改同一寄存器。

**补充**：`volatile REG ^= mask` 仍是读—改—写，不能靠 volatile 保证原子性；只用任务互斥锁也挡不住 ISR。写 1 清零、读有副作用的寄存器不能套用普通读改写。

**来源**：精华 p.21。

<a id="q050"></a>

### 50. 怎样统计二进制中 1 和 0 的个数？

**简答**：统计 1 可循环执行 `x &= x-1`，每次清除最低有效的 1，执行次数就是结果。统计 0 要先确定统计位宽，再用位宽减去 1 的个数。

```c
unsigned count = 0;
while (x != 0) { /* x 为无符号整数 */
    x &= x - 1;
    ++count;
}
```

**补充**：使用无符号类型，避免原题中有符号加减在边界值溢出；32 位值的 0 位数为 `32-popcount(x)`。

**来源**：精简 p.24–25。

<a id="q051"></a>

### 51. 不使用第三个变量，怎样交换两个整数？

**简答**：可用三条独立语句做异或交换：`a^=b; b^=a; a^=b;`，前提是二者为不同的整数对象。加减交换对有符号数有溢出风险，同一对象异或交换会把值清零。

**补充**：工程中通常用临时变量，清楚且容易优化；不要写成没有明确顺序保证的链式异或表达式。多语句宏若必须使用，应包在 do-while(0) 中并避免副作用实参。

**来源**：精简 p.25；精华 p.19–20。

<a id="q052"></a>

### 52. 什么是大端和小端，怎么判断？

**简答**：小端在低地址放低有效字节，大端在低地址放高有效字节。以 0x12345678 为例，从低到高地址，小端为 78 56 34 12，大端为 12 34 56 78。可通过 unsigned char* 观察整数的最低地址字节。

```c
uint32_t x = UINT32_C(0x12345678);
unsigned char first = ((unsigned char *)&x)[0];
/* 0x78 通常表示小端，0x12 通常表示大端 */
```

**补充**：常见 8 位字节平台可用下面例子判断传统大/小端；不要把所有 MCU 一概说成大端。

**来源**：精简 p.141–144。

<a id="q053"></a>

### 53. 怎样做大小端转换？浮点数怎么处理？

**简答**：整数使用无符号掩码和移位交换字节；协议发送和接收也可以按规定顺序逐字节编码解码。浮点数先确认宽度和表示，再用 memcpy 取其对象表示，按协议调整字节顺序。

```c
uint32_t swap32(uint32_t x)
{
    return ((x & UINT32_C(0x000000FF)) << 24) |
           ((x & UINT32_C(0x0000FF00)) << 8)  |
           ((x & UINT32_C(0x00FF0000)) >> 8)  |
           ((x & UINT32_C(0xFF000000)) >> 24);
}
```

**补充**：字节交换不是数值强制类型转换；不能依赖位域布局，不能未经确认就假定所有 float 都是 4 字节 IEEE 754。

**来源**：精简 p.144–145。

<a id="q054"></a>

### 54. 怎样用 C 读写固定地址的硬件寄存器？

**简答**：按芯片手册确认地址、访问权限和宽度，再使用匹配宽度的 volatile 指针或厂商头文件读写。整数到指针转换依赖目标实现；错误地址、非对齐或错误宽度都可能引发故障。

```c
volatile uint32_t *reg =
    (volatile uint32_t *)(uintptr_t)UINT32_C(0x40000000);
uint32_t value = *reg;
*reg = value;  /* 是否允许回写，须由寄存器语义决定 */
```

**补充**：下面是形式示例，地址不对应某个已确认外设。遇到写 1 清零等语义时必须按手册操作。

**来源**：精简 p.145；精华 p.20、47。

<a id="q055"></a>

### 55. 怎样跳转到指定地址执行？和跳转固件一样吗？

**简答**：平台支持时可将有效函数入口转换为签名匹配的函数指针，再调用。该地址必须有合法可执行代码，且当前栈、指令状态与运行环境满足要求。

**补充**：整数到函数指针转换不是通用可移植 C。Cortex-M 还要考虑 Thumb 状态；跳到另一份固件需按引导设计处理向量表、初始 MSP、中断和时钟等，不能只把镜像基地址当普通函数调用。

**来源**：精简 p.145；精华 p.47。

<a id="functions"></a>

## 六、字符串与内存函数

<a id="q056"></a>

### 56. 手写 strlen 的思路和注意点？

**简答**：从字符串起点扫描到第一个 '\0'，累计字符数，不含结束符，返回 size_t。调用方必须提供有效、范围内有终止符的字符串。

```c
size_t my_strlen(const char *s)
{
    size_t n = 0;
    while (s[n] != '\0') ++n;
    return n;
}
```

**补充**：扫描期间不要每次重新调用 strlen；NULL 不是空字符串。

**来源**：精简 p.109；精华 p.12。

<a id="q057"></a>

### 57. 手写 strcpy 的思路和注意点？

**简答**：逐字符复制，直到把 '\0' 也复制过去，返回目标起始指针。目标容量至少为源长度加 1，源目标不能重叠。

```c
char *my_strcpy(char *dst, const char *src)
{
    char *ret = dst;
    while ((*dst++ = *src++) != '\0') { }
    return ret;
}
```

**补充**：保留初始 dest 才能返回起始地址；不是返回局部临时缓冲区。

**来源**：精简 p.109；精华 p.12–13。

<a id="q058"></a>

### 58. 手写 strcat 的思路和注意点？

**简答**：先找到目标字符串的 '\0'，从那里复制源字符串并包含结束符，返回目标起点。容量至少为两串长度之和加 1，二者应为有效字符串且不能重叠。

**来源**：精简 p.109；精华 p.13。

<a id="q059"></a>

### 59. 手写 strcmp 的思路和返回值？

**简答**：同步比较两个字符串，遇到第一个不同字符或结束符时停止。按 unsigned char 的值比较：小于、等于、大于分别返回负数、0、正数。

**补充**：标准只要求返回值的符号，不保证一定为 -1 或 1。

**来源**：精华 p.13–14。

<a id="q060"></a>

### 60. 手写 strstr 的思路和返回值？

**简答**：从主串的每个候选位置开始与子串逐字符比较，匹配成功返回首次匹配位置的指针，找不到返回 NULL；空子串返回主串起点。朴素算法最坏 O(nm)。

**补充**：比较时应使用子串当前下标；原示例的参数/下标和返回类型有混淆，本条按标准函数语义整理。

**来源**：精华 p.14–15。

<a id="q061"></a>

### 61. memset 做什么？能把 int 数组每个元素设成 1 吗？

**简答**：memset 把前 n 个字节设为转换成 unsigned char 后的值，返回目标起点。它按字节填充，不是按元素赋值；给 int 数组 memset(...,1,...) 通常不会得到每个元素等于 1。

**补充**：例如常见 4 字节 int 被填成 0x01010101；通用对象初始化优先用对应类型的初始化或赋值，不能把字节全零等同所有类型的语义零值。

**来源**：精华 p.15。

<a id="q062"></a>

### 62. 手写 memcpy 的思路和限制？

**简答**：把源的 n 个字节复制到目标，返回目标起点。可用 unsigned char 指针逐字节复制；源目标容量和有效性由调用方保证，重叠时行为未定义。

**补充**：处理二进制数据不依赖 '\0'；需要保留源指针的 const 限定。

**来源**：精华 p.15–16。

<a id="q063"></a>

### 63. memmove 和 memcpy 有什么区别，重叠如何处理？

**简答**：memmove 允许重叠，效果等同先保存源内容再写目标。实现可选择从前向后或从后向前复制，防止覆盖尚未读取的字节；memcpy 要求不重叠。

**补充**：手写通用实现不能无条件对无关对象指针用 <、> 比大小；在同一数组内移动可据偏移决定方向，平台地址比较方案需注明实现条件。

**来源**：精简 p.111–112；精华 p.16–17。

<a id="q064"></a>

### 64. memcmp 与 strcmp 有什么区别？

**简答**：memcmp 比较指定 n 个字节，不遇 '\0' 停止；strcmp 比较两个以 '\0' 结尾的字符串。都按 unsigned char 的值确定字典序，返回值只保证负、零、正的含义。

**补充**：不要直接 memcmp 含填充字节的结构体来判断逻辑相等，应按有效字段比较。

**来源**：精华 p.16。

<a id="q065"></a>

### 65. 手写 atoi 的思路，溢出怎么办？

**简答**：依次处理前导空白、可选正负号和十进制数字，用乘 10 加数字累积，遇到非数字停止。实现时在运算前检查范围，明确非法输入与溢出处理策略。

**补充**：标准 atoi 不能可靠区分失败与结果 0，越界转换也不可依赖；工程优先 strtol/strtoul 并检查结束位置和范围。原题的饱和截断实现是自定策略。

**来源**：精简 p.109–110；精华 p.17–18。

<a id="q066"></a>

### 66. 手写 atof 的基本思路？

**简答**：先处理空白和符号，再解析整数部分、小数部分以及可选指数，合成 double 结果。完整实现需处理格式、无有效数字、溢出/下溢及精度问题。

**补充**：面试说明思路即可；工程优先使用 strtod 并检查结束指针和错误信息，简单十进制累加不等价于完整标准转换。

**来源**：精华 p.18–19。

<a id="q067"></a>

### 67. 怎样把整数转换成字符串？itoa 是标准函数吗？

**简答**：itoa 不是标准 C 函数。手写时反复取余得到各位、反转顺序、加符号和 '\0'，处理 0 与最小负数，确保缓冲区足够。工程可用有容量限制的 snprintf。

**补充**：不能直接对最小负 int 取负来求绝对值，否则可能溢出；结果缓冲区要由调用方提供或明确分配/释放责任。

**来源**：精简 p.110–111。

## 七、编译与链接

<a id="q068"></a>

### 68. C 程序从源码到可执行文件经过哪些步骤？

**简答**：预处理展开宏、包含头文件和条件编译；编译做语法语义检查并生成汇编；汇编生成目标文件；链接解析符号并组织代码/数据，得到可执行文件或固件镜像。

**补充**：常见 GCC 对应 -E、-S、-c 及链接调用；交叉编译器的目标平台与运行编译器的电脑可以不同。

**来源**：精简 p.149；精华 p.130。

<a id="q069"></a>

### 69. 如何让一个函数在 main 之前执行？

**简答**：这取决于工具链和启动流程。GCC 可用 constructor 属性注册启动时执行的函数；裸机也可在已建立所需运行环境的启动路径中显式调用初始化函数。

**补充**：这不是可移植标准 C 功能，MCU 启动代码需实际执行相应初始化表。核对：[GCC 属性说明](https://gcc.gnu.org/onlinedocs/gcc/Common-Attributes.html)。

**来源**：精简 p.19–20。

<a id="q070"></a>

### 70. 静态库和动态库有什么区别？

**简答**：静态链接把需要的库代码纳入最终程序，部署通常无需另带该库；动态链接由装载/运行机制解析库引用，可支持共享和单独更新，但依赖兼容的运行环境。普通 MCU 固件常用静态链接。

**补充**：不能说静态链接必定复制整个库，也不能一概断言静态库总更快或更安全；动态库不是 C++ 专属。

**来源**：精华 p.131。

<a id="q071"></a>

### 71. Makefile 的基本规则和自动变量是什么？

**简答**：规则写成“目标: 依赖”，配方描述怎样生成目标；GNU make 常用 `$@` 表示目标，`$<` 表示第一个依赖，`$^` 表示去重后的全部依赖。

**补充**：原资料的文件名替换函数拼写应为 patsubst；构建工具题作为选读，不扩展 Linux 命令。

**来源**：精华 p.131–132。

## 八、数据结构基础（选读）

<a id="q072"></a>

### 72. 顺序表/数组和链表有什么区别？

**简答**：数组连续存放，按下标访问 O(1)，中间插删通常需移动元素；链表用指针连接，定位通常 O(n)，已知相关节点时插删可 O(1)。数组局部性好、开销小；链表灵活但有指针和分配成本。

**补充**：不能说链表插删从查找开始就一定 O(1)。

**来源**：精华 p.112–113。

<a id="q073"></a>

### 73. 双向链表怎样插入和删除节点？

**简答**：在 p 与 next 之间插入 s，先设置 s 的前后链接，再更新相邻节点；删除 q 时，把 q 的前驱和后继连接，再按所有权释放 q。必须处理表头、表尾、空表与并发访问。

**补充**：资料只给中间节点情况；尾节点的 next 可能为 NULL，不能直接解引用。

**来源**：精华 p.113–114。

<a id="q074"></a>

### 74. 循环队列怎样判断空和满？

**简答**：用数组加 head/tail，索引用取模或回绕更新。若预留一个槽位，head==tail 表示空，下一 tail==head 表示满；也可额外记录 count 或状态位区分空满。

**补充**：预留槽位方案的可用容量为数组长度减 1；count 方案要同步维护。并发环形缓冲区还需考虑原子性和内存顺序。

**来源**：精华 p.114–116。

<a id="q075"></a>

### 75. 乱序收到带 size、offset 的数据，怎样按序输出？

**简答**：维护下一个期望偏移 expected；先验证偏移加长度不溢出，再保存未连续片段并按 offset 排序。只输出从 expected 开始能连续拼接的部分，之后更新 expected；缺口补齐前保留后续数据。

**补充**：要明确重复/重叠策略、缓冲容量、所有权、超时和总长度/结束标记；不知道总大小也不能无限申请内存，不能无依据把全部缓存一次发送。

**来源**：精华 p.114。

<a id="q076"></a>

### 76. 二叉树、满二叉树、完全二叉树和二叉搜索树分别是什么？

**简答**：二叉树每个节点至多两个孩子；国内常见定义的满二叉树每层都满；完全二叉树除最后一层外都满，最后一层靠左排列；二叉搜索树按约定满足左子树键小、右子树键大。

**补充**：英文 full/proper 有时指每个节点有 0 或 2 个孩子，需与 perfect 区分。平衡树限制高度，二叉堆满足父子大小关系但不等于搜索树。

**来源**：精华 p.116–117。

<a id="q077"></a>

### 77. 怎样构造哈夫曼树？编码有什么意义？

**简答**：把各权值当作单节点树，反复取最小的两棵合并，权值相加，直到只剩一棵。沿边分配 0/1 得到前缀编码，让常见符号通常使用较短码字，降低平均编码长度。

**补充**：最小堆实现构造通常 O(n log n)，用于压缩，不等于保证所有机器指令执行更快。

**来源**：精华 p.117–118。

<a id="q078"></a>

### 78. 二叉搜索树为什么会退化？

**简答**：顺序插入等情况可能使树近似链表，树高从 O(log n) 变成 O(n)，查找和插删随之变慢。可采用 AVL、红黑树等平衡结构；不是所有二叉树都天然平衡。

**来源**：精华 p.118。

<a id="q079"></a>

### 79. 红黑树是什么？优缺点是什么？

**简答**：红黑树是通过颜色规则和旋转保持高度为 O(log n) 的二叉搜索树，查找、插入和删除最坏 O(log n)，还能支持有序遍历。代价是实现和维护复杂、节点有额外信息。

**补充**：核心规则：根和 NIL 为黑，红节点不接红孩子，从节点到各 NIL 的黑节点数相同。它不要求左右子树高度差最多 1。

**来源**：精华 p.118–119。

<a id="q080"></a>

### 80. B 树和 B+ 树有什么区别？

**简答**：二者都是平衡多路查找树，通过增加分支降低树高，适合块存储访问。常见 B 树在内部和叶节点保存记录；B+ 树内部节点主要做索引，记录集中在叶层，叶节点常按序连接，适合范围查询。

**补充**：此题是通用数据结构选读，暂不扩展文件系统或数据库实现。

**来源**：精华 p.120。

<a id="q081"></a>

### 81. 图常见的存储方式是什么？BFS 和 DFS 怎么实现？

**简答**：邻接矩阵空间 O(V²)，查边方便；邻接表空间 O(V+E)，更适合稀疏图。BFS 用队列按层访问，DFS 用递归或显式栈深入访问，都要记录 visited，非连通图还需从未访问顶点继续。

**来源**：精华 p.120–121。

<a id="q082"></a>

### 82. 最小生成树的 Prim 和 Kruskal 思路是什么？

**简答**：在连通无向带权图中，Prim 每次选连接已选集合与未选集合的最小权边；Kruskal 按边权排序，依次选不会形成环的边，常用并查集判环。

**补充**：目标是连接所有顶点且边权总和最小，不等于从某点出发的最短路径；非连通时可得到最小生成森林。

**来源**：精华 p.121–122。

<a id="q083"></a>

### 83. Dijkstra 和 Floyd 求最短路径有什么区别？

**简答**：Dijkstra 求单源最短路径，标准版本要求边权非负；Floyd 用每个顶点作中间点更新任意两点距离，时间 O(V³)、空间 O(V²)。Floyd 可处理负边，但不能把经过负环的路径当有限最短路径。

**来源**：精华 p.122。

<a id="q084"></a>

### 84. 哈希冲突怎样解决？C 里可用哪些结构？

**简答**：常见方案是链地址法和开放地址法；通过合适哈希函数、控制装载率及扩容重建减少冲突。C 可用数组做直接索引/计数，或自行实现哈希表，也可用经审核的第三方库。

**补充**：uthash 不是标准 C 头文件；资料的 std::set/map 等容器不收录，哈希性能还要说明平均情况与退化风险。

**来源**：精华 p.123–124。

## 九、C 算法面试题（选读）

<a id="q085"></a>

### 85. 怎样删除未排序单链表中的重复节点？

**简答**：保留第一次出现的节点：可用集合或值域有限时的标记数组记录已见值，通常 O(n)；不允许额外缓冲时，逐个节点扫描后续并删除重复项，O(n²)、额外空间 O(1)。

**补充**：删除前保存 next，按节点所有权决定是否 free；不能使用已释放的节点继续遍历。

**来源**：精简 p.40–41、48–49。

<a id="q086"></a>

### 86. 怎样找链表倒数第 k 个节点？

**简答**：先让快指针走 k 步，再让快慢指针一起走；快指针到 NULL 时，慢指针就是倒数第 k 个。时间 O(n)、空间 O(1)，先处理 k<=0 和链表不足 k 个节点。

**来源**：精简 p.41–42。

<a id="q087"></a>

### 87. 怎样找链表中间节点？

**简答**：慢指针每次一步，快指针每次两步；快指针到末尾时慢指针位于中间。时间 O(n)、空间 O(1)，两个中间节点时通过循环条件选择前一个或后一个。

**来源**：精简 p.42–43。

<a id="q088"></a>

### 88. 怎样反转单链表？

**简答**：维护 prev、cur、next：先保存 cur->next，再把 cur->next 指向 prev，随后推进 prev 和 cur，最后 prev 是新表头。时间 O(n)、空间 O(1)。

**补充**：递归也能实现，但需要 O(n) 调用栈，MCU 长链表通常优先迭代。

**来源**：精简 p.43–44。

<a id="q089"></a>

### 89. 怎样判断链表有环，求入口并安全解除环？

**简答**：快慢指针相遇说明有环；相遇后一个从头、另一个从相遇点每次走一步，重新相遇处为入口。若业务允许解除环，沿环找入口的前驱，再把其 next 置 NULL。

**补充**：时间 O(n)、空间 O(1)；检查 fast 和 fast->next，未确认是否允许修改时只检测、不拆环。

**来源**：精简 p.44–45；精华 p.113。

<a id="q090"></a>

### 90. 怎样找两个无环单链表的交点？

**简答**：两个指针分别走 A、B，到末尾后切换到另一条链，走过相同总路程后相遇；相遇的节点为交点，都到 NULL 则不相交。时间 O(m+n)、空间 O(1)。

**补充**：比较节点地址，不是比较节点值；本方法假设两链无环。

**来源**：精简 p.46–47。

<a id="q091"></a>

### 91. 怎样判断链表是回文？

**简答**：快慢指针找中点，反转后半链，再逐节点比较前后两段；时间 O(n)、空间 O(1)。若要求不改变输入，比较后把后半链恢复。

**来源**：精简 p.47–48。

<a id="q092"></a>

### 92. 怎样合并两个有序链表？

**简答**：用哑节点和尾指针，反复取两表头中较小的节点接到结果，最后接上剩余部分。时间 O(m+n)，迭代额外空间 O(1)。

**补充**：确认是否可复用原节点；递归实现会使用调用栈。

**来源**：精简 p.50–51。

<a id="q093"></a>

### 93. 二叉树先序、中序、后序和层序怎样实现？

**简答**：先序是根左右，中序是左根右，后序是左右根；递归对应调整访问节点的位置，非递归用显式栈记录待处理节点/访问状态。层序用队列，出队访问并把孩子入队。

**补充**：时间均 O(n)。递归栈随树高 h 增长；层序队列随最大层宽增长。MCU 实现需检查栈/队列容量。

**来源**：精简 p.51–69。

<a id="q094"></a>

### 94. 怎样求二叉树最大深度？

**简答**：空树返回 0；非空节点返回 `1 + max(左深度,右深度)`。遍历每个节点，时间 O(n)、递归额外空间 O(h)。

**补充**：这里按路径节点数定义深度；若按边数计高度，要调整基准。

**来源**：精简 p.69–70。

<a id="q095"></a>

### 95. 怎样判断两棵二叉树相同？

**简答**：同时递归比较：都空则相同，仅一个为空则不同；两者均非空时，要求节点值相等，且左右子树分别相同。

**补充**：既要比值也要比结构；不能用普通数值 0 代表空节点再序列化比较，因为 0 可能是合法节点值。

**来源**：精简 p.70–72。

<a id="q096"></a>

### 96. 怎样判断二叉树是否平衡？

**简答**：后序遍历一次计算高度，同时检查左右高度差是否超过 1；遇到不平衡向上返回失败标志。时间 O(n)、空间 O(h)。

**补充**：不要对每个节点重复求整棵子树高度，否则最坏可退化到 O(n²)。

**来源**：精简 p.72–73。

<a id="q097"></a>

### 97. 怎样求最大连续子数组和？

**简答**：维护以当前元素结尾的最大和：`cur=max(a[i],cur+a[i])`，再更新整体最大值。时间 O(n)、空间 O(1)。

**补充**：要求子数组非空时用首元素初始化，不能把答案固定从 0 开始，否则全负数组会错；累加要考虑溢出。

**来源**：精简 p.74–75。

<a id="q098"></a>

### 98. 怎样原地移除数组中指定值？

**简答**：读指针遍历，遇到不等于目标值的元素就写入写指针位置并推进写指针，最后写指针给出新长度。时间 O(n)、空间 O(1)，保留剩余元素相对顺序。

**来源**：精简 p.75–76。

<a id="q099"></a>

### 99. 怎样把两个有序数组合并到第一个数组？

**简答**：第一个数组要有 m+n 容量，从两段有效数据的末尾比较，把较大值写到结果末尾，再向前推进，避免覆盖未读数据。时间 O(m+n)、空间 O(1)。

**来源**：精简 p.76–78。

<a id="q100"></a>

### 100. 怎样找多个小写字符串都出现的字符，保留重复次数？

**简答**：每个字符串用 26 项数组统计字符次数，对每个字符取各串计数的最小值，并按该次数输出。时间与总字符数和字符串数量成线性关系，辅助计数空间为固定 26 项。

**补充**：返回多个动态字符串时，要明确外层数组和每个字符串的释放责任。

**来源**：精简 p.78–79。

<a id="q101"></a>

### 101. 怎样求数组的中心索引？

**简答**：先求总和，再从左向右维护 leftSum；若 `leftSum == total-leftSum-a[i]`，i 就是最靠左的中心索引。时间 O(n)、空间 O(1)。

**补充**：索引 0 或末尾也可合法，一侧无元素时和为 0；求和类型要防溢出。

**来源**：精简 p.79–81。

<a id="q102"></a>

### 102. 其他数字出现两次，怎样找两个只出现一次的数字？

**简答**：全部异或得到两数的异或值，找其中一个为 1 的位，把数组按该位分成两组，各组再异或得到两个答案。时间 O(n)、空间 O(1)。

**补充**：位处理使用无符号表示；可用 `mask=x & (0u-x)` 取得最低的 1，避免对最小有符号值取负。

**来源**：精简 p.81–82。

<a id="q103"></a>

### 103. 其他数字出现三次，怎样找只出现一次的数？

**简答**：对每一位统计 1 的数量，再对 3 取余，留下的位组成答案。固定位宽 w 时，时间 O(wn)、额外空间 O(w)，固定宽度下可视为 O(n)。

**补充**：包括符号位，移位和掩码使用无符号类型；转回有符号值时要考虑目标实现与输入范围。

**来源**：精简 p.82–83。

<a id="q104"></a>

### 104. 0～n 中缺失一个数字，怎样查找？

**简答**：把 0～n 和数组全部元素异或，成对数字抵消，剩下的就是缺失值。时间 O(n)、空间 O(1)。

**补充**：前提是 n 个元素互不重复且均在 0～n；求和法也可，但中间结果要防溢出。

**来源**：精简 p.83–85。

<a id="q105"></a>

### 105. 怎样把数组偶数放前面、奇数放后面？

**简答**：用左右指针，左侧跳过偶数，右侧跳过奇数，交换错位元素并继续，时间 O(n)、空间 O(1)。

**补充**：这种原地方法通常不保持相对顺序；若要求稳定分组，需要另行设计。

**来源**：精简 p.85–86。

<a id="q106"></a>

### 106. 怎样找距离不超过 k 的重复元素？

**简答**：用哈希表记录每个值最近一次出现的索引；再次遇到时检查索引差是否不超过 k，然后更新最近索引。平均时间 O(n)，空间 O(n)，或用大小受限的滑动窗口。

**补充**：k<=0 时不存在两个不同索引满足条件；C 哈希表需自己实现或选库。

**来源**：精简 p.86–87。

<a id="q107"></a>

### 107. 有序数组中，怎样找出现次数超过 25% 的元素？

**简答**：利用相同值在有序数组中连续：扫描相邻相等段并计数，或令 d=floor(n/4)，检查 `a[i]==a[i+d]` 的候选。时间 O(n)、空间 O(1)。

**补充**：题设保证恰好存在答案时可直接返回，否则需要验证或给失败结果；检查 i+d 不越界。

**来源**：精简 p.87–88。

<a id="q108"></a>

### 108. 怎样判断有效山脉数组？

**简答**：长度至少为 3，先严格上升到峰值，峰值不能在两端，再严格下降到末尾；全部走完才是山脉。时间 O(n)、空间 O(1)。

**补充**：相邻相等不满足严格上升或下降。

**来源**：精简 p.88–90。

<a id="q109"></a>

### 109. 怎样求最长连续递增序列的长度？

**简答**：遍历数组，当前值大于前一个值则连续计数加 1，否则重置为 1；同步更新最大长度。时间 O(n)、空间 O(1)。

**补充**：空数组返回 0；这是连续片段，不是可跳过元素的最长递增子序列。

**来源**：精简 p.91–92。

<a id="q110"></a>

### 110. 怎样判断括号字符串有效？

**简答**：左括号入栈，右括号必须与栈顶匹配并弹出；扫描结束栈为空才有效。时间 O(n)，最坏空间 O(n)。

**补充**：先检查栈空再弹出，固定数组栈必须检查容量，不能直接套资料中的固定 3500 大小。

**来源**：精简 p.92–94。

<a id="q111"></a>

### 111. 怎样做十进制字符串相加或二进制字符串相加？

**简答**：从低位向高位处理，用 carry 保存进位；每位结果为 sum%base，进位为 sum/base，直到两个串和进位都处理完。最后加 '\0' 并按需要反转。

**补充**：结果至少留最大输入长度+2 字节（一个进位、一个结束符）；不能返回局部数组，也不要丢失 malloc 起始地址后只返回内部地址让调用方 free。

**来源**：精简 p.94–96。

<a id="q112"></a>

### 112. 怎样原地反转字符串？

**简答**：左右下标相向移动并交换字符，时间 O(n)、空间 O(1)。只操作有效字符范围，不把字符串末尾 '\0' 当作待反转字符。

**补充**：输入必须可写；字符串字面量不能原地修改，空串时避免无符号长度减 1 下溢。

**来源**：精简 p.96。

<a id="q113"></a>

### 113. 怎样反转字符串中每个单词，保持单词顺序？

**简答**：扫描定位每个单词的起止下标，在单词内部用双指针交换；空格位置和单词排列保持。时间 O(n)、空间 O(1)。

**来源**：精简 p.96–97。

<a id="q114"></a>

### 114. 怎样只反转字符串中的元音字母？

**简答**：两端指针各自找到下一个元音，交换后继续相向推进，时间 O(n)、空间 O(1)。

**补充**：按题意识别 a/e/i/o/u 及其大写形式，y 不算元音；跳过字符时也要检查左右边界。

**来源**：精简 p.97–98。

<a id="q115"></a>

### 115. 怎样验证忽略大小写和非字母数字的回文串？

**简答**：双指针从两端开始，跳过不参与比较的字符，把有效字符统一大小写后比较。全部匹配则为回文，时间 O(n)、空间 O(1)。

**补充**：使用 ctype 函数时，把 char 转为 unsigned char 后再传入，避免负 char 值导致非法调用；按题意空串为回文。

**来源**：精简 p.98–99。

<a id="q116"></a>

### 116. 最多删除一个字符，怎样判断能否成为回文？

**简答**：双指针找到第一处不相等时，分别验证跳过左字符或跳过右字符后的剩余区间；任一为回文即可。时间 O(n)、空间 O(1)。

**来源**：精简 p.99–100。

<a id="q117"></a>

### 117. 怎样按字符出现频率降序排列字符串？

**简答**：先统计频率，再按频率排序或分桶，按次数把同一字符连续写入结果。有限字符集用计数数组即可。

**补充**：结果保留所有原字符，大小写按题意分别统计，缓冲区留终止符。

**来源**：精简 p.101–102。

<a id="q118"></a>

### 118. 怎样统计字符串中的单词个数？

**简答**：按原题“连续非空格字符为一个单词”，统计从串首/空格转入非空格的位置数量，时间 O(n)、空间 O(1)。

**补充**：若要把制表符、换行等也当分隔符，需另行约定，不自动改变原题规则。

**来源**：精简 p.102–103。

<a id="q119"></a>

### 119. 怎样找前 k 个高频单词？

**简答**：先用哈希表计数，再按次数降序、同频时按字典序升序排序取前 k 个；也可用大小为 k 的堆减少候选维护开销。

**补充**：C 中明确字符串比较、内存所有权和堆容量；不能依赖未收录的 C++ 容器。

**来源**：精简 p.103–104。

<a id="q120"></a>

### 120. 怎样检测一个单词的大写形式是否合法？

**简答**：允许全部大写、全部小写，或仅首字母大写。可统计大写字符个数并检查第一个字符，时间 O(n)、空间 O(1)。

**补充**：原题输入为非空英文字母串；其他字符需定义处理规则。

**来源**：精简 p.104–105。

<a id="q121"></a>

### 121. 怎样找多个字符串的最长公共前缀？

**简答**：以首串为基准按字符位置比较所有字符串，遇到任一串结束或字符不同就停止；此前部分即公共前缀。

**补充**：输入列表为空时返回空结果；输出缓冲区或返回切片需要说明生命周期与是否允许修改输入。

**来源**：精简 p.105–106。

<a id="q122"></a>

### 122. 两个字符串的最长特殊序列怎么求？

**简答**：按原题定义，若两串完全相同则返回 -1；否则答案是较长串的长度。因为较长串不可能是更短串的子序列，同长度不同串也不互为完整子序列。

**来源**：精简 p.106。

<a id="q123"></a>

### 123. 多个字符串的最长特殊序列怎么求？

**简答**：按长度降序检查候选，若某串不是其他任一串的子序列，就返回其长度；全都不满足返回 -1。对子序列关系用双指针判断。

**补充**：重复字符串不能作为候选；不能直接套用两个字符串只比较长度的结论。

**来源**：精简 p.106–107。

<a id="q124"></a>

### 124. 怎样统计连续二进制子串？

**简答**：把串按连续相同字符分组，相邻两组长度为 a、b 时可贡献 min(a,b) 个合法子串，累计即可。时间 O(n)、空间 O(1)。

**补充**：合法子串必须是两个连续块，0 和 1 数量相同；不是任意数量相等的子串都满足题目。

**来源**：精简 p.108–109。

<a id="sorting"></a>

## 十、排序及优化（选读）

<a id="q125"></a>

### 125. 常见排序算法怎样比较？稳定是什么意思？

**简答**：比较时间、额外空间、稳定性和输入规模。稳定排序保持相等关键字的原相对顺序；常见稳定实现包括冒泡、直接插入和归并，常见不稳定实现包括选择、快速、堆和希尔。

**补充**：下表指常见数组实现，复杂度中的递归栈也应计入空间。

**来源**：精简 p.112–125；精华 p.124–126。

<a id="q126"></a>

### 126. 快速排序的过程、复杂度和改进方法是什么？

**简答**：选基准、分区、递归处理左右区间；平均时间 O(n log n)，最坏 O(n²)。可用随机基准/三数取中，重复值多时三路分区，小区间切换插入排序；需要最坏界时可用带回退的混合排序。

**补充**：普通原地快排无需归并式的“合并结果”；递归空间平均 O(log n)、最坏 O(n)，受控地递归较小侧可限制栈深。

**来源**：精简 p.112–114；精华 p.124–125。

<a id="q127"></a>

### 127. 冒泡排序原理是什么，怎么优化？

**简答**：比较相邻元素，把较大的逐步移到后面；每轮结束一个最大值到位。记录本轮是否交换，无交换则提前结束；也可记录最后交换位置缩小下一轮范围。

**补充**：常见实现稳定、额外空间 O(1)，平均/最坏时间 O(n²)，有序且提前退出时 O(n)。

**来源**：精简 p.114–115。

<a id="q128"></a>

### 128. 怎样构造大根堆和做堆排序？适合 Top-K 吗？

**简答**：从最后一个非叶节点 `n/2-1` 向前做下沉调整，O(n) 建大根堆；不断交换堆顶与末尾，再缩小堆并下沉，排序 O(n log n)。流式求最大的 k 个数通常维护大小为 k 的小根堆。

**补充**：数组索引从 0 开始，孩子为 2i+1、2i+2；迭代下沉额外空间 O(1)。Top-K 方法时间 O(n log k)、空间 O(k)，并非所有场景都应先完整排序。

**来源**：精简 p.115–117；精华 p.125–126。

<a id="q129"></a>

### 129. 直接插入排序原理和适用场景是什么？

**简答**：维持前部有序，取下一个元素，把更大的元素右移后插入正确位置。稳定、空间 O(1)，有序时 O(n)，平均/最坏 O(n²)，适合小规模或近乎有序的数据。

**来源**：精简 p.117–119。

<a id="q130"></a>

### 130. 选择排序原理和优化是什么？

**简答**：每轮从未排序区找最小值，与未排序区起点交换，直到全部有序。常见实现不稳定，空间 O(1)，最好/平均/最坏时间都 O(n²)。

**补充**：一轮找最大和最小可减少部分扫描轮次，但仍为 O(n²)，还需处理交换后位置变化。

**来源**：精简 p.119–120。

<a id="q131"></a>

### 131. 归并排序原理、复杂度和优化是什么？

**简答**：把序列分成两部分，分别排序，再线性合并；时间 O(n log n)，常见数组实现需 O(n) 辅助空间。相等时先取左侧可保持稳定。可用迭代归并、小区间插入排序、已整体有序时跳过合并。

**补充**：资料把使用临时数组的实现标成原地排序不严谨；链表归并的辅助空间分析与数组不同。

**来源**：精简 p.120–124。

<a id="q132"></a>

### 132. 希尔排序是什么，时间复杂度固定吗？

**简答**：按递减增量把数组分组做插入排序，最终增量为 1 完成整体排序。通常原地、空间 O(1)、不稳定。时间复杂度取决于增量序列，不能统一写成 O(n log n)。

**来源**：精简 p.124–125。

| 常见数组排序实现 | 最好时间 | 平均时间 | 最坏时间 | 额外空间 | 通常稳定 |
|---|---|---|---|---|---|
| 冒泡（提前退出） | O(n) | O(n²) | O(n²) | O(1) | 是 |
| 直接插入 | O(n) | O(n²) | O(n²) | O(1) | 是 |
| 简单选择 | O(n²) | O(n²) | O(n²) | O(1) | 否 |
| 快速 | O(n log n) | O(n log n) | O(n²) | 平均 O(log n)，最坏 O(n) 调用栈 | 否 |
| 堆（迭代下沉） | O(n log n) | O(n log n) | O(n log n) | O(1) | 否 |
| 归并（辅助数组） | O(n log n) | O(n log n) | O(n log n) | O(n) | 是 |
| 希尔 | 取决于增量 | 取决于增量 | 取决于增量 | O(1) | 否 |

## 易错说法速查

| 容易背错的说法 | 面试应改成 |
|---|---|
| volatile 能保证线程安全 | 它保留特定可观察访问；并发同步仍需锁/原子操作等 |
| static 变量在调用过程中不变 | 它保留生命周期和上次值，仍然可以修改 |
| 数组名就是常量指针 | 数组是对象，多数表达式中转换为首元素指针 |
| 二维数组就是 int** | 连续二维数组退化为行指针，和 int** 布局不同 |
| C 参数固定从右向左压栈 | 传参由 ABI 决定，实参求值顺序还需单独判断 |
| sizeof 永远编译期求值 | 固定大小类型通常如此，可变长数组相关情况例外 |
| 结构体大小就是各成员之和 | 还要计算成员之间及末尾填充；以 ABI 为准 |
| union 只取最大成员长度 | 还要满足联合体整体对齐 |
| 位域顺序只由大小端决定 | 位域布局由实现决定，不能当固定协议格式 |
| 2048 元素的局部数组一定爆栈 | 看元素宽度、调用开销和实际栈预算 |
| 指针未显式初始化都是随机值 | 自动指针不能直接使用，静态存储期指针默认为空 |
| free 后把 p 置空就没有悬空指针 | 其他别名仍可能悬空，需要明确所有权和生命周期 |
| malloc 后把指针改成字符串就完成复制 | 只是改变指针，可能丢失分配块；复制内容应写入有效缓冲区 |
| 无符号/有符号运算都能随意回绕 | 无符号按模运算，有符号溢出是未定义行为 |
| 普通归并排序 O(n) 缓冲仍算原地 | 常见辅助数组实现需要 O(n) 额外空间 |
| 希尔排序固定 O(n log n) | 复杂度取决于增量序列 |
